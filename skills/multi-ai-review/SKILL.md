# 여러 AI 토의·검수

우선순위: 실행 환경의 시스템 프롬프트·설정 > 사람의 지시 > 이 스킬. 부딪혀 결과가 달라졌으면 보고에 적는다.

## 순서
1. 처음 쓰는 CLI·모델은 "Reply OK" 한 줄 요청으로 탐침하고, 429·인증 오류면 사람에게 알리고 다른 모델로 폴백한다.
2. 검수 모델은 읽기 전용으로 띄우고 업로드·외부 API 호출을 브리프에서 금지한다(호출 형식은 `codex-delegation`).
3. 검수에 넘길 원고는 최종 형식(대본이면 읽을 문장 그대로, 글이면 발행 형태)으로 맞춘 뒤 보낸다.
4. 검수는 원고 성격과 상관없이 매번 돌리고, "이미 반영했다"는 이유로 건너뛰지 않는다.
5. 양이 많으면 5개씩 묶어 보낸다.
6. 토의는 라운드로 진행한다.
   | 라운드 | 할 일 |
   |---|---|
   | R1 독립 제안 | 모델마다 서로의 답을 보지 않고 따로 제안한다(앵커링 방지). |
   | R2 교환·공격 | 서로의 제안을 주고 약점을 공격하게 한다. |
   | R3 수렴 | 살아남은 안과 버린 안을 이유와 함께 정리한다. |
   | R4 역할·파일럿 | 누가 무엇을 하는지와 작게 시험할 범위를 정한다. |
7. 라운드마다 UTF-8 브리프 파일·짧은 ASCII 프롬프트·결과 파일(`-o`)을 남기고 백그라운드로 돌린다.
8. 약한 주장은 토론으로 정하지 않고 조사나 작은 파일럿으로 잰다(`hypothesis-experiment`).
9. 다른 모델이 낸 수치·URL·인용은 API 조회나 원문 열기로 다시 확인한다(`fact-check-gate`).
10. 의견마다 아래 채택 필터를 통과시켜 채택·기각 표를 만들고, 판단은 메인이 한다.
11. 최종 정리는 사람이 볼 표로 만들고 폰 폭에서 표가 깨지지 않는지 본다.

## 점검
| 채택 필터 | 기준 |
|---|---|
| 근거 | 원고·데이터·원문에서 근거 위치를 댈 수 있는 지적만 채택한다. |
| 사람 기준과 충돌 | 사람이 정해 둔 형식·톤·방향과 부딪히는 제안은 기각한다. |
| 없던 사실 | 원고에 없던 사실·수치·사례를 끼워 넣는 수정은 빼낸다. |
| 뉘앙스 변조 | 고친 문장이 원래 주장의 세기·대상·범위를 바꾸지 않았는지 원문과 나란히 대조한다. |
| 비속어·유행어 | 모델이 넣은 비속어·슬랭은 채택하지 않는다. |
| 다수결 | 여러 모델이 같은 의견을 내도 근거가 없으면 채택 수에 넣지 않는다. |
| 안정 편향 | 모델들이 무난한 쪽으로 모이면 R3 전에 "새로움" 기준을 따로 세워 다시 평가한다. |
| 가짜 출처 | 모델이 준 URL은 열어서 200 응답과 내용 일치를 확인하기 전까지 쓰지 않는다. |
| 획일화 | 같은 계열 모델만 쓰지 않고 서로 다른 모델을 2개 이상 섞는다. |

| 모델에 맡길 것 | 맡기지 않을 것 |
|---|---|
| 대량 후보 생성 | 취향·재미에 대한 go/no-go 판정 |
| 약점 공격·반례 찾기 | 최종 채택·기각 |
| 사실·수치 검증 | 사람 기준을 바꾸는 결정 |

## 하지 않는 것
- 모델이 기각했다는 이유만으로 사람이 고른 방향을 접지 않는다.
- 검수 결과를 그대로 원고에 일괄 반영하지 않는다.
- 브라우저 화면을 띄워 검수시키지 않고 헤드리스 CLI로 돌린다.
- 검수 응답 전문을 버리지 않고 결과 파일로 남긴다.
- 사람에게 보일 문안의 최종 수정을 모델에게 맡기지 않는다.
