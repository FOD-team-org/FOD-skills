# 범위를 지킨 수정과 검증

## 언제
- 파일을 지정한 수정·리팩터링을 맡았을 때
- 하위 에이전트에게 코드 수정을 맡길 때(명세에 이 스킬 규칙을 넣는다)
- 테스트가 권한·네트워크 오류로 실행되지 않았을 때

## 범위
- 시작과 끝에 `git status --short`를 찍는다. 이미 있던 커밋 안 된 변경은 내 것이 아니다. 건드리지 않는다.
- 지정한 파일만 고친다. 범위 밖 문제는 고치지 않고 `파일:줄`과 한 줄 설명으로 보고한다.
- 문구·데이터를 옮길 때는 글자 그대로 옮긴다. 다듬지 않는다.
- 테스트 기대값을 낮추지 않는다. 골든 파일·스냅샷을 다시 만들어 통과시키지 않는다.
- 커밋, push, stash, reset, checkout으로 작업 트리를 바꾸지 않는다. 사람이나 메인이 지시한 경우만 예외다.

## 검증 근거 3단계
| 단계 | 뜻 | 보고 표기 |
|---|---|---|
| 실행·통과 | 테스트·빌드를 실제로 돌려 통과 | 명령과 통과 수 |
| 정적 확인만 | 타입 검사·린트·코드 읽기만 함 | "실행 안 함, 정적 확인" |
| 실행 못 함 | 권한(EPERM)·네트워크·런타임 부재로 실패 | "실행 0건"과 오류 줄, 밖에서 돌릴 명령 |
- 권한 오류로 테스트가 0건 실행됐으면 통과가 아니다. "실행 못 함"으로 쓴다.
- 데스크톱 단위 테스트 통과는 모바일 시뮬레이터·실기기 동작의 근거가 아니다. 무엇에서 돌았는지 쓴다.
- 테스트 도구의 캐시 폴더가 샌드박스 밖이면 실패한다. 캐시 경로를 쓰기 가능한 임시 폴더로 지정한다(예: Jest `--cacheDirectory`).

## 기준선 비교
- 타입 검사·린트 오류는 수정 전(HEAD) 결과와 비교해 "새로 생긴 것"만 내 책임으로 본다. 원래 있던 오류 수를 같이 적는다.
- 새로 만든 추적 안 된 파일은 `git diff`에 안 나온다. `git diff --no-index /dev/null <파일>`로 보여 준다.

## 마지막 보고 칸
| 칸 | 내용 |
|---|---|
| 바꾼 파일 | 경로 목록 |
| 검증 | 단계(위 표)와 명령·결과 수 |
| 범위 밖 발견 | 파일:줄과 한 줄 |
| 작업 트리 | 시작·끝 `git status --short` 차이 |
| 남은 위험 | 실행 못 한 검증, 확인 안 된 가정 |

## 하지 않는 것
- 실행 못 한 테스트를 통과로 보고
- 범위 밖 "김에 고치기", 기대값 낮추기
- 사람의 커밋 안 된 변경 덮어쓰기
