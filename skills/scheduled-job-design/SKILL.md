# 예약 작업 설계

등록·백업·멈춤 감지·복구는 routine-ops, macOS 등록은 launchd-ops를 따른다. 이 스킬은 작업 자체를 어떻게 짜는지 다룬다.

## 언제
- 새 루틴·cron 작업을 만들 때
- 루틴이 비싸거나, 자주 실패하거나, 매번 "없음"만 낼 때
- 등록부의 모델·전달 대상·일정을 한꺼번에 바꿀 때

## 실행 방식 고르기
| 작업 | 방식 |
|---|---|
| 스크립트 실행, 파일 동기화, 감시 | LLM 없이 스크립트만. 토큰을 쓰지 않는다 |
| 수집·요약 | 낮은 등급 모델 |
| 판단·운영·코드 위임 | 높은 등급 모델 |
- 결정적 파이프라인 위에 LLM 층을 얹을 때: 하위 작업자는 읽기만 하고, 쓰기는 부모가 한다. 데이터가 없으면 지어내지 않고 data_gap으로 표시한다. 표준 출력이 비면 알림을 보내지 않는다.
- 모델을 바꾼 뒤에는 설정 파일이 아니라 다음 실행 기록에서 실제 모델을 확인한다.

## 시간 예산
- 단순 3~10분, 조사 10~25분, 코딩 위임 20~40분을 기준으로 잡는다. 정해진 상한(예: 45분)을 넘으면 부분 결과로 마감한다. 1시간짜리 정상 경로는 설계하지 않는다.
- 타임아웃 값이 총 실행 시간인지 무활동 시간인지 확인한다.
- 대화 세션에 거는 예약은 만료 기한이 있을 수 있다. 만료 전에 갱신 일정을 잡는다.

## 무인 실행의 제약
- 무인 실행은 질문도 승인도 받을 수 없다. 승인이 필요한 도구는 막힌다. 처음부터 허용된 경로(정해진 스크립트)로 짠다.
- 백그라운드 완료 알림을 따로 켜면 같은 메시지가 두 번 갈 수 있다. 충분한 타임아웃을 주고 포그라운드로 돈다.
- 손으로 한 번 돌려 성공한 것은 예약 실행이 된다는 증거가 아니다. 첫 예약 실행의 기록을 확인한다.

## 산출물과 실패
- 시작할 때 STARTED, 중간에 PARTIAL 체크포인트를 쓰고, 끝났을 때만 정식 경로로 올린다. 프롬프트에 "산출물 먼저"라고 쓰는 것만으로는 강제되지 않는다.
- 의미 있는 내용이 없으면 "없음"이라고 쓴다. 억지로 채우지 않는다.
- 실패하면 어디서 실패했고 무엇을 재시도했는지만 쓴다. 빈칸을 짐작으로 채우지 않는다.
- 작업마다 연속 실패 수를 세고, 정한 수에 이르면 스스로 멈추고 알린다.
- 실행마다 토큰·시간 사용량을 한 줄로 남긴다.

## 수율 보정
점수 게이트로 후보를 거르는 루틴(아이디어, 종목, 리드)에 적용한다.
- 통과 수와 실행당 비용을 같이 기록한다.
- 연속 N회(예: 10회) 통과 0이면 게이트 재보정이나 빈도 축소를 안건으로 올린다. 같은 비용으로 계속 돌리지 않는다. 매번 0건이면서 실행당 수백만 토큰을 쓴 루틴이 있었다.
- 상위 리뷰 단계는 하위 루틴의 점수를 그대로 믿지 않고 다시 채점한다.
- 탈락 사유를 남겨 다음 보정의 근거로 쓴다.

## 서버 cron 엔드포인트
- 마감 시간을 취소 신호(AbortSignal 등)로 모든 하위 작업에 전한다. 응답만 끊으면 작업은 뒤에서 계속 돈다.
- 트랜잭션·락 제한 시간보다 짧게 끝나도록 커밋 여유를 둔다.
- 상태 기록은 완료 시각을 조건으로 upsert한다. 늦게 끝난 옛 실행이 새 결과를 덮지 않게 한다.
- DB에는 정해진 형식의 오류 코드만 저장한다. 원문 오류 메시지는 저장하지 않는다.
- 호출 비밀값은 해시 다이제스트를 상수 시간 비교한다. 비밀값이 설정 안 됐으면 404, 틀리면 401.
- 플랫폼 제약(요금제별 최소 주기, 외부 호출기의 타임아웃)을 먼저 확인하고 작업을 그 안에 들어가게 쪼갠다.

## 등록부 일괄 변경
1. 바꾸기 직전에 `<파일>.bak.<이유>.<YYYYMMDD_HHMMSS>`로 백업한다.
2. 요청된 칸(모델, 전달 대상, 일정)만 바꾸고 diff가 그 칸뿐인지 본다.
3. 되돌릴 때 파일을 통째로 복원하지 않는다. 마지막 실행 시각·카운터가 사라진다. 필요한 칸만 되돌린다.
4. 테스트는 등록부 사본으로 한다.
5. 런타임을 재시작하면 옛 PID·새 PID를 적고, 1회성 검증 작업으로 적용을 확인한다. 확인 전에는 "저장됨, 검증 예정"으로 보고한다.
- 다른 기기로 옮길 때 그 기기의 작업·전달·인증 ID를 재사용하지 않는다. 기기별 값은 환경 변수로 받는다.
- 전달 채널을 옮길 때는 위험이 낮은 작업부터 옮기고, 중요한 작업은 관찰 기간 동안 두 채널에 같이 보낸다.

## 하지 않는 것
- 결정적 작업에 LLM 쓰기, 끝없는 시간 예산
- 빈 결과를 억지로 채우기, 0건 루틴 방치
- 등록부 통째 복원, 확인 전 "적용됨" 보고
