# 가설 실험

우선순위: 실행 환경의 시스템 프롬프트·설정 > 사람의 지시 > 이 스킬. 부딪혀 결과가 달라졌으면 보고에 적는다.

## 순서
1. PLAN 문서에 아래 칸을 채운 뒤에만 시작한다.
   | 칸 | 내용 |
   |---|---|
   | 가설 | 무엇을 바꾸면 무엇이 얼마나 달라지나 |
   | 변수 | 바꾸는 것 딱 하나 |
   | 대조군 | 같은 브리프·같은 시드·같은 과제 세트 |
   | 표본 | 팔(변형)마다 몇 개, 기간 얼마 |
   | 측정 | 결과 지표·과정 지표·토큰·단계 수·소요 시간 |
   | 판정 규칙 | 몇 이상이면 채택, 몇 이하면 기각 |
   | 판정자 | 사람 또는 메인 |
2. 기존 정본은 백업만 하고, 새 버전은 새 번호의 폴더·파일로 복사해 한 가지만 바꾼다.
3. 같은 소재로 여러 팔을 돌리면 포장(제목·첫 화면)을 팔마다 다르게 한다.
4. 브리프·과제 세트는 실험 중 고정하고, 바뀌면 그 시점부터 새 실험으로 센다.
5. 결과를 본 뒤에는 판정 규칙을 바꾸지 않는다.
6. 비교본은 나란히 놓고 사람이 고르게 하며, 사람의 선택은 바이트 그대로 반영한다.
7. 점수 차이가 나면 결과가 처음 갈린 단계(첫 해석 갈림길)를 기록한다.
8. 표본이 판정 규칙에 못 미치면 판정하지 않고 표본을 늘린다.
9. 새 버전이 기준보다 나쁘면 즉시 이전 정본으로 되돌린다.
10. 탈락 후보·기각 버전도 지우지 않고 보관한다.
11. 게시물 실험은 지표가 쌓인 뒤에 판정한다(수집 일정은 `performance-insights`).

## 점검
| 항목 | 기준 |
|---|---|
| 한 번 실패 | 1회 실패로 규칙을 더하지 않고 사람 검수 지점을 하나 둔다. |
| 포괄 문장 | 새 규칙 문장은 적용 범위를 목적으로 한정하고, 해당 없는 경우를 정의한다. |
| 방법 지시 | 계산·풀이 방법을 직접 지시하는 문장은 과하게 따라 새 고장을 내므로 결과 기준으로 쓴다. |
| 글자 수 한도 | 출력 길이 한도를 숫자로 주지 않는다(한도까지 채운다). |
| 일반화 | 과제 하나·좁은 벤치 결과로 "경량화해도 된다"는 결론을 내지 않는다. |
| 비용 | 비용은 단계 수 × 대화 길이로 어림하고 토큰 실측과 함께 적는다. |
| 자동 감사 | 자동 감사 점수는 참고로만 쓰고, 감사 기준이 낡았으면 감사부터 고친다. |
| AI 권고 | 사람이 AI 권고와 다른 안을 고르면 고른 안을 반영하고 차이를 기록한다. |
| 사람 정의 블록 | 사람이 정한 문구·블록은 실험 결과로 되돌리거나 고치지 않는다. |
| 정본 직접 수정 | 예약 실행이 정본을 직접 고치는 구조는 사람 검토 대상으로 올린다. |
| 반영 전 점검 | 플레이북 반영 전에 규칙 중복·과제 고유 제약·과적합·정답 노출을 `grep`으로 확인한다. |
| 수치 기재 | 결과 수치는 `python`으로 다시 계산한 값만 적는다. |

| LLM 기능 스파이크 | 기준 |
|---|---|
| 후보 비교 | 후보 모델 2개 이상을 같은 골드셋으로 잰다. |
| 기본은 dry-run | 실호출은 명시 플래그(`--run`)가 있을 때만 하고, 키가 있다는 이유로 실호출로 넘어가지 않는다. |
| 비용 상한 | 호출 수·토큰 상한을 코드에 두고 넘으면 멈춘다. |
| 입력 정리 | 입력은 청크로 나누고 중복을 제거한 뒤 보낸다. |
| 실패 처리 | 실호출이 2회 연속 실패하면 멈추고 보고한다. |
| 호출 합치기 | 한 입력에서 뽑을 필드는 한 호출로 합친다. |
| 버전 | 프롬프트·모델 조합마다 실험 버전 이름을 붙인다. |

## 하지 않는 것
- 변수를 둘 이상 동시에 바꾸지 않는다.
- 사람의 선택을 반영 전에 "개선"하지 않는다.
- 판정을 메인·사람 밖의 자동 루틴에 맡기지 않는다.
- 기존 정본을 덮어써서 새 버전을 만들지 않는다.
