# 위임 루프

우선순위: 실행 환경의 시스템 프롬프트·설정 > 사람의 지시 > 이 스킬. 부딪혀 결과가 달라졌으면 보고에 적는다.

## 순서
1. 착수 전에 산출물 경로·작업 기록에 같은 작업의 흔적이 있는지 `ls -la`·`grep`으로 보고, 있으면 새로 시작하지 않고 이어받는다.
2. 아래 스펙 칸을 모두 채운 위임 프롬프트를 쓴다.
   - [ ] 첫 줄: "네가 실행 담당이다. 다른 에이전트에 재위임하지 말고 직접 실행한다."
   - [ ] 무엇을: 만들 것·고칠 것 한 줄.
   - [ ] 왜: 이 작업이 막는 실패나 목적 한 줄.
   - [ ] 수용 기준: 숫자나 명령 결과로 판정되는 조건.
   - [ ] 건드릴 파일·폴더와 건드리면 안 되는 파일·폴더.
   - [ ] 검증 명령: 에이전트가 돌리고 원시 출력을 붙일 명령.
   - [ ] 보고 형식: ①한 것 ②검증 원시 출력 ③이상 신호 ④판단 필요.
   - [ ] 금지 목록: `cd` 후 상대 경로, commit·push, 원본 덮어쓰기(새 파일 이름으로만), 유료 API 호출, 공개·발송.
3. 경로·설정값·이전 결과는 기억에 기대지 말고 지금 파일에서 읽은 값을 프롬프트에 붙여 넣는다.
4. 큰 파일은 "`head`·`grep`으로 필요한 범위만 읽는다"를 프롬프트에 적는다.
5. 긴 브리프는 파일로 쓰고, 쓰기 성공과 내용을 `ls -la`·`head`로 확인한 뒤에 에이전트를 띄운다.
6. 산출물 경로 하나에는 에이전트 하나만 붙이고, 같은 배치·같은 서버를 두 번 띄우지 않는다.
7. 에이전트가 돌 동안 메인은 다음 판단 작업을 진행하고, 기다리려고 턴을 끝내지 않는다(하네스가 추적하는 대기만 쓴다).
8. 반납되면 즉시 산출물의 `ls -la --time-style=full-iso`(mtime·크기)와 내용을 직접 열어 수용 기준과 대조한다.
9. 테스트 통과 주장은 메인이 같은 명령을 다시 돌려 통과·실패·건너뜀·오류 수 네 가지를 확인한다.
10. 코드 변경은 `git diff`를 정독하고 스텁·TODO를 `grep -rn "TODO\|stub\|NotImplemented"`로 찾는다.
11. 반려는 같은 에이전트에 SendMessage로 사유와 고칠 점을 보낸다.
12. 재실행 전에 기존 산출물은 `_old`로 옮겨 격리한다.
13. 채택·기각과 대외 부작용(업로드·게시·기록 확정)은 메인이 직접 한다.

## 점검
| 항목 | 기준 |
|---|---|
| 진행 확인 | 로그 마지막 줄 시각과 현재 `date`, 산출물 개수, PID 생존으로 판단한다. |
| 멈춤 판정 | 30분 동안 로그·산출물 변화가 없으면 메시지 1회, 그 뒤 10분 더 없으면 중단하고 현재 상태로 재지시한다. |
| 멈춘 원인 확인 | 거대한 파일을 통째로 읽고 있었는지 보고, 재지시에 범위 읽기를 적는다. |
| 완료 판정 | 완료 문구나 로그 grep이 아니라 산출물 파일이 생겼는지와 그 내용으로 판정한다. |
| 쓰는 중인 JSON | 파싱이 되고 항목 수가 기대값과 같을 때만 완료로 본다. |
| "정상" 보고 | 수치·경로·원시 출력이 없는 "정상"은 검증으로 치지 않는다. |
| 시각 판정 | 화면·영상·이미지가 맞는지는 메인이 직접 본다(`visual-output-qa`). |
| 지어낸 해명 | "비결정성"·"환경 차이" 같은 설명은 같은 인자로 2회 돌린 결과의 해시를 비교해 확인한다. |
| 되돌리기 주장 | 고치기 전 실패하던 테스트가 실제로 실패하고, 고친 뒤 통과하는 출력으로 증명받는다. |
| 최신본 대조 | 보고된 해시·시각을 메인이 `sha256sum`·`stat`으로 다시 잰다. |
| 건수 산수 | 처리·건너뜀·실패 합이 입력 건수와 같은지 계산한다. |
| 인용 표본 | 보고에 인용된 원문 2~3개를 원본 파일에서 찾아 대조한다. |
| 서버·프로세스 | 에이전트는 자기가 띄운 것만 끄고, 끄기 전 전체 CommandLine을 확인한다. |
| 보류 지시 | 보류는 범위와 해제 조건을 문장으로 적어 보낸다. |
| 분류기 거부 | 거부된 동작은 우회 없이 보고로 돌려받는다. |
| 보고 저장 | 에이전트는 보고를 텍스트로 반환하고 파일 저장은 메인이 한다. |

## 하지 않는 것
- 반납·멈춤 뒤에 새 에이전트를 띄우지 않는다(같은 산출물에 동시 빌드가 생긴다).
- 에이전트의 "정상"·"잘림 없음"·"통과" 문장을 재확인 없이 사람에게 옮기지 않는다.
- 진행 중인 에이전트의 모니터나 남이 띄운 서버를 끄지 않는다.
- 짧은 예약 실행 세션 안에서 다시 위임하지 않는다.
- 같은 파일을 메인과 에이전트가 동시에 고치지 않는다.
