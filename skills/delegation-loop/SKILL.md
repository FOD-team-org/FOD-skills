# 위임 루프

## 언제
- 하위 에이전트(서브에이전트, 헤드리스 CLI, 예약 작업 세션)에게 일을 맡길 때.
- 오래 도는 배치(렌더·생성·수집·학습)를 맡기고 기다릴 때.

## 위임 명세 틀
하위 에이전트는 이 대화를 보지 못한다. 명세만 읽고 끝낼 수 있게 쓴다.
| 칸 | 쓰는 것 |
|---|---|
| 머리말 | "너는 실행 담당이다. 다른 에이전트에게 다시 맡기지 말고 직접 수행한다." |
| 무엇·왜 | 할 일, 이 일이 필요한 이유 한 줄 |
| 수용 기준 | 끝났다고 볼 산출물. 파일 경로·개수·수치로 쓴다 |
| 건드릴 파일 | 읽을 파일, 쓸 파일(절대 경로). 그 밖은 쓰지 않는다 |
| 금지 | 이번 일에 맞는 것만: 새 파일명으로만 쓰기, 커밋·push·게시·삭제 금지, 유료 API 금지 |
| 값 | 해시·ID·설정값은 기억에 맡기지 않고 붙여 넣는다 |
| 검증 방법 | 실행할 명령과 기대 출력 |
| 보고 형식 | ① 한 것 ② 검증 출력 원문 ③ 이상 신호 ④ 판단 필요. 시각 판정은 쓰지 않고 수치·경로만 쓴다 |
- 출처를 다루는 일이면 "출처 문서의 문장을 직접 읽고 인용한다"를 넣는다.
- 큰 파일은 통째로 읽지 말고 필요한 부분만 검색해 읽으라고 적는다.
- 게시 1건 같은 짧은 예약 작업 세션에는 하위 에이전트 호출 자체를 금지한다. 헤드리스 CLI는 에이전트 도구를 끈 상태로 띄운다.
- 명세를 파일로 쓰면 파일이 실제로 있는지 확인한 뒤 에이전트를 띄운다.

## 동시 실행 충돌 막기
- 띄우기 전에 출력 경로에 다른 세션의 산출물이 있는지 본다: 폴더 존재, 메타 파일의 생성 시각, 작업 로그 항목.
- 내가 만들지 않은 산출물이 있으면 새로 만들지 않고 이어받아 검수한다.
- 출력 경로(작업 폴더·워크트리·서버 포트) 하나에 에이전트 하나만 둔다.
- 남이 띄운 서버·프로세스를 끄지 않는다. 쓰이는 포트면 다른 포트를 쓴다.
- 같은 배치를 두 번 띄우지 않는다. 정본 파일은 쓰기 전에 존재 여부부터 본다.

## 장시간 작업 감독
- 명세에 넣는다: 기다리려고 턴을 끝내지 않는다. 하네스가 추적하는 백그라운드 대기만 쓴다. 중간에 반납하지 않는다.
- 진행은 보고가 아니라 실측으로 본다: 진행 로그 마지막 줄 시각과 지금 시각, 산출물 개수, 프로세스 생존.
- 출력이 오래 없으면 메시지로 한 번 묻는다. 그 뒤에도 변화가 없으면 멈추고 현재 상태에서 다시 지시한다. 기다릴 한도는 작업 길이에 맞게 미리 정한다.
- 로그가 끊겼다고 죽었다고 단정하지 않는다. 디스크 산출물과 프로세스로 확인한다.
- 멈출 때는 에이전트만 끄지 않는다. 남은 자식 프로세스를 실행기부터 서버 순으로 정리하고 포트가 비었는지 본다.
- 보류를 지시할 때는 보류 범위와 해제 조건을 같이 준다.

## 반납 직후 확인
1. 산출물이 있는지, 수정 시각이 이번 작업 시각인지 본다.
2. 보고의 수치·ID 목록을 로그·파일과 맞춘다. 처리 건수와 원장 건수는 산수로 맞춘다.
3. 테스트는 직접 다시 돌린다. 전체·통과·실패·건너뜀 네 수를 본다.
4. diff에서 스텁·TODO·하드코딩을 검색하고 호출부까지 따라간다.
5. 화면·이미지 결과는 메인이 직접 본다(visual-output-qa).
6. 미실행이거나 가짜 완료면 같은 에이전트에 메시지로 다시 지시한다. 새 에이전트를 띄우지 않는다. 늦게 도착하는 하위 작업과 겹친다.

## 하지 않는 것
- "정상", "통과", "무관하다", "원래 그랬다"는 보고를 검증으로 쓰지 않는다.
- 그럴듯한 기술 해명(비결정성, 캐시 탓)을 재현 없이 받지 않는다. 같은 입력으로 두 번 돌려 해시를 비교한다.
- 메인과 하위 에이전트가 같은 파일을 동시에 고치지 않는다.
- 게시·발송·삭제를 하위 에이전트에게 넘기지 않는다.
