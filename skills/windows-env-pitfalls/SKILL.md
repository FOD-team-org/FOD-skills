# Windows 작업 함정

이 목록은 프로젝트 지침과 위임 프롬프트에 붙여 쓴다.

## 언제
- Windows에서 스크립트·도구를 실행하거나 위임할 때
- 한글이 깨지거나, 같은 명령이 이유 없이 실패할 때
- 세션에서 설치한 도구가 사람의 터미널에서 안 보일 때

## 파이썬
- `python`으로 실행한다. `python3`·`py`는 쓰지 않는다. `python3`가 스토어 스텁이면 설치 페이지가 열린다.
- 실행할 때 `PYTHONIOENCODING=utf-8`을 준다. `-I` 모드에서는 `sys.stdout.reconfigure(encoding="utf-8")`.
- 작업 폴더에 표준 모듈과 같은 이름의 파일(select.py, json.py 등)을 두지 않는다. 깨끗한 하위 폴더에서 실행한다.

## 한글 읽기·쓰기
| 상황 | 함정 | 대처 |
|---|---|---|
| 콘솔 출력 | cp949로 깨져 내용(예: "금지" 메모)을 놓친다 | 판단에 쓸 한글은 파일 읽기 도구로 직접 읽는다. 출력은 UTF-8 파일로 쓰고 읽는다 |
| PowerShell 쓰기 | `Set-Content`·`Add-Content` 기본이 ANSI 코드페이지 | `-Encoding utf8`을 주거나 파일 쓰기 도구를 쓴다 |
| 셸 리다이렉트 | `>`로 한글 파일을 쓰면 인코딩·BOM이 섞인다 | 파일 쓰기 도구로 만든다 |
| 긴 한글 heredoc | 따옴표·역슬래시가 깨진다 | 파일로 쓴 뒤 `python 파일.py` |
| here-string으로 `python -c` | 인자가 깨진다 | .py 파일로 쓴다 |
| sed 치환 | 역슬래시 이스케이프가 문자열을 깨고, Git Bash `sed -i`는 CRLF를 LF로 바꾼다 | 스크립트로 바꾸고 치환 횟수가 기대값인지 assert, 줄바꿈 보존 |
| 정규식 | 셸 이스케이프로 깨진다 | 스크립트 파일 안에 둔다 |
| SQL | 한글 SQL을 인자로 넘기면 깨진다 | UTF-8 파일을 `-f`로. psql 옵션은 접속 URL 앞에 |
| 웹 페이지 | euc-kr 페이지가 깨진다 | 응답 인코딩을 확인해 디코드 |
- 새 파일은 BOM 없는 UTF-8. 기존 파일은 원래 줄바꿈(CRLF·LF)을 확인하고 그대로 쓴다.

## 도구에 긴 한글 본문 보내기
- MCP·API 도구 인자에 긴 한글 본문을 모델이 직접 옮겨 적지 않는다. 옮겨 적다 글자가 바뀐 사고가 있었다.
- 본문을 UTF-8 파일로 저장하고, 스크립트가 파일 바이트를 읽어 그대로 보낸다.
- 보낸 뒤 공개본을 받아 원본과 대조한다(글자 수·해시).

## 셸 차이
- PowerShell 5.1에는 `&&`가 없고, 네이티브 명령의 stderr를 오류 레코드로 감싼다. 테스트 출력이 필요하면 Bash에서 `2>&1`.
- 백그라운드 셸에는 PATH가 없을 수 있다. 실행 파일은 전체 경로로 부르고, 종료 코드 0만 믿지 말고 산출물을 확인한다.
- Git Bash가 `/sdcard` 같은 인자를 Windows 경로로 바꾸면 `MSYS_NO_PATHCONV=1`.
- stdin이 열려 있으면 기다리는 CLI가 있다. 비대화형 호출은 `< /dev/null`.
- 문서에 적는 시각은 `date` 출력으로 쓴다.
- 위임 프롬프트에 자동 수정 명령(`lint --fix` 류)을 넣지 않는다.

## 패키지형 앱의 AppData 가상화
- 패키지(MSIX)로 설치된 앱 안에서 도는 세션이 `%APPDATA%`·`%LOCALAPPDATA%`에 쓰면 패키지 전용 폴더로 빠진다. 세션 안에서는 보이지만 사람의 터미널에는 없다. HKCU 레지스트리도 대부분 가상화되고 사용자 환경 변수 키만 실제로 써진다.
- 증상: 세션에서는 "설치 성공", 사람 터미널에서는 파일 없음·실행기 경로 오류.
- 대처: 도구는 홈 폴더 바로 아래(예: `~/.local`)에 설치한다. 설치 위치를 정하는 환경 변수를 사용자 환경 변수로 둔다. AppData로 가는 설치(winget·`npm -g`·`pip --user`·설치 프로그램)는 피한다.
- 확인: 설치 뒤 컨테이너 밖에서 실행해 본다. WMI `Win32_Process` Create로 띄우고 출력을 홈 아래 파일로 받는다. 같은 파일 경로가 안에서는 있고 밖에서는 없으면 가상화된 것이다.
- 세션 임시 폴더도 가상화 영역일 수 있다. 바깥 프로세스와 파일을 주고받을 때는 홈 바로 아래 경로를 쓴다.

## 경로
- 공백·한글 경로는 따옴표로 감싼다. 한글 경로에서 실패하는 도구(빌드·패키지 분석 도구 등)는 ASCII 경로로 복사해 실행한다.
- 긴 경로(워크트리 등)는 잡고 있는 프로세스를 먼저 끄고 `cmd /c rmdir /s /q \\?\<경로>`로 지운다. 에이전트가 테스트를 백그라운드에 남기지 않게 한다.
- 정션으로 옮긴 폴더는 양쪽 경로가 같은 내용을 가리킨다. 정리·집계 스크립트가 같은 파일을 두 번 세지 않게 한다.

## 셸 도구가 통째로 고장 날 때
- 증상: 모든 Bash 호출이 `-c: line N: unexpected EOF`처럼 같은 따옴표 오류로 실패한다. 메시지가 `파일: line N`이 아니라 `-c: line N`이면 래퍼 문자열 문제다.
- 원인 후보: 세션 시작 훅이 세션 환경 파일에 같은 줄을 반복해 덧붙이고, 동시 세션이 쓰는 도중에 읽혀 잘린 줄이 명령에 섞인다.
- 즉시 대처: 그 세션을 재시작한다. 근본 대처: 훅에 중복 추가 방지를 넣는다. 플러그인이 업데이트되면 패치가 사라지므로 재발 시 새 버전에 다시 적용한다.
