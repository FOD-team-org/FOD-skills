# 짧은 영상 제작 공정

우선순위: 실행 환경의 시스템 프롬프트·설정 > 사람의 지시 > 이 스킬. 부딪혀 결과가 달라졌으면 보고에 적는다.

## 순서
1. 조사: 소재 후보를 고르기 전에 제작 로그와 빌드 메타를 검색해 이미 다룬 소재를 뺀다.
2. 대본: 사람이나 메인이 직접 쓰고, 사실은 `fact-check-gate`, 말투는 `korean-voice-review`로 본다.
3. 후킹 검수 뒤 사람 승인 관문을 한 번 두고, 승인은 에피소드 폴더의 `GATE_OK` 파일로 남긴다.
4. 소스: 원본을 받아 쓸 구간과 권리 기록을 남긴다(`asset-rights-check`).
5. 편집: 에피소드를 데이터 JSON(장면·구간·자막·크롭)으로 적고, 크롭 좌표는 `visual-output-qa`의 실측으로 정한다.
6. 미리보기 관문: 스토리보드와 첫 3초 후킹 띠 이미지를 보고 통과해야 빌드한다.
7. 빌드: JSON을 읽어 새 폴더에만 출력하고, 무거운 렌더는 한 번에 하나만 돌린다.
8. 자동 검수: 라우드니스·WER(`audio-tts-qa`), 자막 2줄 이하, 자막 겹침, 최소 글자 크기를 qa.json에 기록한다.
9. 패키지 관문: mp4, 표지, 폰 화면 미리보기, qa.json을 한 묶음으로 넘기고 관문마다 수정은 한 가지씩 한다.
10. 게시는 이 공정 밖에서 `safe-publish`로 한다.

## 단계 규칙
| 항목 | 기준 |
|---|---|
| 단계 순서 | 앞 단계 DONE 표시와 필수 산출물 파일을 확인한 뒤에만 다음 단계를 시작한다 |
| 담당 | 단계마다 다른 에이전트가 맡고, 대본 단계는 위임하지 않는다 |
| 병렬 | 에피소드 하나 안에서는 병렬 금지, 에피소드끼리는 병렬 허용 |
| 출력 스키마 | 기존 산출물 파일을 읽어 형식을 맞추고 추측으로 새 형식을 만들지 않는다 |
| 소재 기준 | 쌓아 둘 편수를 채우려고 소재 기준을 낮추지 않는다 |
| 샘플 | 시험판은 별도 폴더에 `publish:false`로 두어 게시 도구가 건너뛰게 한다 |
| 엔진 동결 | 빌더를 고치기 전 `.bak`을 남기고, 고친 뒤 기준 프레임 이미지와 비교한다 |
| 캐시 키 | 실행 시각이 아니라 입력 내용의 해시로 만든다 |
| 키트 | 자주 쓰는 장면은 키트로 두고, 키트로 안 되는 장면이 나오면 45분 안에 멈추고 보고한다 |
| 대본 묶음 | 대본은 여러 편을 한 번에 써 두고 빌드는 순서대로 돌린다 |

## 싱크 검증
1. fps는 정수(30)로 고정하고 29.97을 섞지 않는다.
2. 파트 i의 프레임 수는 `ceil(경계_i × 30) − ceil(경계_(i−1) × 30)`으로 정하고 각 파트를 따로 렌더한다.
3. 영상은 `ffmpeg -f concat -safe 0 -i list.txt -an -c:v copy video.mp4`로 이어 붙인다.
4. 오디오는 따로 만들어 길이를 맞춘다: `-af "apad=whole_dur=<총초>,atrim=0:<총초>"`
5. 먹싱은 `ffmpeg -i video.mp4 -i audio.m4a -map 0:v -map 1:a -c copy final.mp4`로 하고 `-shortest`를 쓰지 않는다(마지막 프레임이 잘린다).
6. 빌더에 구간을 넘길 때는 전체 길이를 덮는 구간 하나로 넘긴다.
7. 총 프레임: `ffprobe -v error -select_streams v:0 -count_frames -show_entries stream=nb_read_frames,r_frame_rate -of csv=p=0 final.mp4` 값이 마지막 경계 프레임 수와 같아야 한다.
8. 프레임 간격: `ffprobe -v error -select_streams v:0 -show_entries frame=pts -of csv=p=0 final.mp4` 의 이웃 차이가 한 가지 값뿐이어야 한다.
9. 컷 위치: `ffmpeg -i final.mp4 -vf "select='gt(scene,0.2)',showinfo" -f null -` 의 pts_time × 30이 각 경계 프레임 P_i ±1 안이어야 한다(showinfo의 n은 선택 뒤 순번이라 쓰지 않는다).
10. 슬롯이 조금 남으면 프레임 복제(tpad) 대신 7% 이하 `setpts` 감속으로 채운다.
11. 화면 확인은 각 P_i의 경계 타일로 한다(`visual-output-qa`).

## 하지 않는 것
- 채널·브랜드마다 다른 말투·색·편성 규칙을 이 공정 문서에 넣지 않는다, 프로젝트 문서에 둔다.
- 같은 에피소드를 두 에이전트가 동시에 빌드하지 않는다.
- 먹싱에 `-shortest`를 쓰지 않는다.
- 검수에 걸린 판을 그대로 둔 채 같은 폴더에 다시 빌드하지 않는다.
