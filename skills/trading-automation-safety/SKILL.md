# 자동매매 안전

전략의 수익성 검증은 backtest-validation, 새 경로를 관찰로 먼저 돌리는 절차는 shadow-lane-cutover를 따른다.

## 언제
- 주문을 낼 수 있는 코드·설정·예약 작업을 만들거나 바꿀 때
- 봇이 이상한 주문을 냈거나, 주문을 안 냈거나, 상태를 모를 때
- 사람이 실주문 전환·중지·전략 교체를 물을 때

## 관찰과 실주문 분리
- 기본값은 관찰(주문 안 냄)이다. 주문 허용 플래그는 설정 해시에 묶어, 설정이 바뀌면 허용이 풀리게 한다.
- 관찰용 클라이언트에는 주문 메서드 자체가 없게 만든다. 플래그 하나로 막는 것보다 확실하다.
- 실주문은 별도 서비스로 두고, 승인을 받아서만 설치한다. 관찰 서비스가 떠 있으면 실주문 설치를 거부하게 한다.
- 실주문 시작은 사람의 명령으로만 한다. 에이전트는 시작 명령을 준비해 건넨다.
- 웹 로그인 화면 자동화보다 공식 API를 쓴다.

## 판단과 주문의 분리
- LLM은 주문 티켓(종목, 방향, 수량, 지정가, 근거)만 쓴다. 제출은 검증을 통과한 티켓만 결정적 코드가 한다.
- LLM을 매매 판단 경로에 넣지 않는 쪽이 기본이다. 넣으면 결정적 결과와 비교하는 관찰 기간을 먼저 둔다(shadow-lane-cutover).

## 주문 전 게이트
| 게이트 | 기준 |
|---|---|
| 주문 종류 | 시장가 금지. 지정가와 가격 보호 범위 |
| 시간 | 정규 거래 시간만. 휴장일 달력으로 판정 |
| 신선도 | 티켓 유효 시각(valid_until), 호가 나이 상한 |
| 중복 | 같은 종목·방향의 미체결 주문이 있으면 거부. 티켓 ID는 유일 |
| 한도 | 일일 한도는 상한이지 채울 목표가 아니다 |
| 수량 | 한도에 걸리면 조용히 줄이지 않고 거부하고 알린다 |
| 데이터 | 오래됐거나 출처끼리 다르면 DATA_BLOCKED_NO_ORDER. 데이터 문제를 NO_ORDER(판단 결과)로 꾸미지 않는다 |
- 제출 전에 파일 잠금(LOCK_EX)으로 티켓을 점유한다. 제출 결과를 모르면(SUBMIT_UNKNOWN) 대사(reconcile)가 끝날 때까지 다시 보내지 않는다.
- 중복 방지 장부는 정리 작업 대상에서 뺀다.
- 미체결 주문은 시간 제한 뒤 취소하는 코드를 둔다. 봇을 멈춰도 거래소에 걸린 주문은 취소되지 않는다는 것을 운영 문서에 적는다.
- 알림 중복 방지 기록은 발송이 성공한 뒤에 쓴다.

## 보고
- 신호, 제출, 체결을 다른 사건으로 보고한다. 체결은 거래 내역·체결 화면에서 확인한 것만 체결이라고 쓴다.
- 상태는 하트비트 나이로 판정한다. 코드 지문이 돌고 있는 프로세스와 다르면 "재시작 필요"로 보고한다.
- 나중에 복원한 기록에는 RECONSTRUCTED와 원천 데이터 해시를 단다.
- 로그·보고에서 키처럼 보이는 줄은 가린다.

## 실주문 변경 통제
- 실주문 경로의 코드 변경은 실패하는 테스트를 먼저 쓰고(RED) 통과시킨 뒤(GREEN), 서로 다른 검수 3건을 받고, 배포할 스테이징 해시를 고정한다.
- 전략을 퇴역시킬 때는 사슬 전체(신호 → 티켓 → 제출 → 알림)의 플래그를 끈다. 자격 증명은 지우지 않고 둔다.

## 사고 대응
1. 원천 데이터로 신호를 독립적으로 다시 계산해 봇의 판단과 비교한다.
2. 서비스를 에이전트가 끄지 않는다. 멈추는 명령을 준비해 사람에게 준다.
3. 수익성 질문에는 과최적화를 의심하고, 단순 보유와 비교한 수치로 답한다.

## 하지 않는 것
- 사람 명령 없는 실주문 시작, 승인 없는 실주문 설치
- 시장가 주문, 조용한 수량 축소, 데이터 결함을 판단 결과로 꾸미기
- 확인하지 않은 체결 보고
