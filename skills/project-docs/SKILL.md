# 프로젝트 문서 체계

우선순위: 실행 환경의 시스템 프롬프트·설정 > 사람의 지시 > 이 스킬. 부딪혀 결과가 달라졌으면 보고에 적는다.

## 순서
1. 루트에 아래 문서를 둔다.
   | 문서 | 담는 것 |
   |---|---|
   | 지침 문서(`AGENTS.md`·`CLAUDE.md`) | 실행 규칙·금지·읽을 순서 |
   | PRD | 무엇을 왜 만드는지 |
   | 디자인 문서 | 화면·톤 기준 |
   | 판단 기록 | `judgment`의 판단대기·가정 문서 |
   | 작업 정본(runbook) | 실행법 한 장 |
2. `docs/` 아래는 `작업일지/`·`검수/`·`결정기록/`·`설계/`·`위임스펙/`·`가이드/`로 나눈다.
3. 작업 정본 한 장에 인프라·스택·실행 명령·기본값·검증 수치·오류 대응·버전 고정·산출물 해시를 모은다.
4. 정책·문법·금기 목록·경로 지도도 같은 정본 체계 안에 두고 따로 흩지 않는다.
5. 사람이 결정한 내용은 결정 문서 하나에만 적고, 다른 문서는 그 항목을 링크로 가리킨다.
6. 작업 항목에 ID 체계(예: `T-001`)와 상태값(대기·진행·검수·완료·보류)을 정해 지침 문서에 적는다.
7. 지침 문서에 세션 시작 때 읽을 문서와 종료 때 남길 기록(작업일지 한 항목·바뀐 정본 줄)을 적는다.
8. 파일 인코딩 규칙(UTF-8, BOM 없음, LF)을 지침 문서와 위임 프롬프트 양쪽에 복사해 둔다.
9. 리서치 저장소는 판단 저장소(후보·판정·근거)와 제작 폴더(원본·산출물)를 나누고, 큰 파일은 저장소에 넣지 않는다.
10. 저장소의 구조와 규칙은 루트 `README.md`에 적고 문서 템플릿을 둔다.
11. 형식을 바꿀 때는 백업을 만들고 문서 2~3개로 시범 전환해 확인한 뒤 넓힌다.
12. 정본이 바뀌면 같은 작업에서 정본을 가리키는 문서도 같이 고친다.

## 점검
| 항목 | 기준 |
|---|---|
| 줄글 0 | 사람이 읽을 문서는 표·체크 목록만 쓰고, 두 문장 이상 이어진 문단이 있으면 칸으로 쪼갠다. |
| 한 칸 한 사실 | 표 한 칸·목록 한 항목에는 사실 하나만 둔다. |
| 서술은 사람 | 문서를 설명하는 서술 문단은 비워 두고 사람이 쓴다(설명 문서 형식은 `explain-doc`). |
| 결정 항목 형식 | 결론 → 이유·버린 대안 → 근거 → 약점 순서의 칸으로 쓴다. |
| 후보 목록 | 후보마다 고른 것·버린 것 체크와 이유·근거 칸을 둔다. |
| 따라 하기 | 다른 실행자가 정본만 보고 같은 명령을 돌려 같은 검증 수치를 얻을 수 있는지 본다. |
| 링크 | 상대 링크가 깨지지 않았는지 `grep -o "](\.\?[^)]*)"`로 뽑아 파일 존재를 확인한다. |
| 설계도 | 흐름·고장 지도는 `design-doc`로 만든다. |
| 기존 파일 | 정리할 때 기존 파일은 옮기기만 하고 지우지 않는다. |

## 하지 않는 것
- 지침 문서에 "완성된 문장으로 쓴다" 같은 줄글을 부르는 규칙을 넣지 않는다.
- 같은 결정을 여러 문서에 따로 적지 않는다.
- 문서 형식을 저장소 전체에 한 번에 일괄 변환하지 않는다.
- 판단 저장소에 영상·대용량 원본을 넣지 않는다.
- 사람이 쓸 서술을 AI가 미리 채우지 않는다.
