# 비공개 서비스 접근 보호

목표: 허용한 사람만 들어오고, 인증 없이는 돈이 드는 기능에 닿지 못하며, 누가 언제 들어왔는지 남는다.

## 언제
- 집·사무실 PC에서 외부 접속이 되는 웹 서비스를 열 때
- 기존 서비스에 AI 호출처럼 호출마다 비용이 드는 기능을 붙일 때
- 허용한 사람 말고는 모두 막아 달라는 요청을 받았을 때

## 설계 기준
| 항목 | 기준 |
|---|---|
| 기본 | 모든 경로를 막고 허용 목록의 경로만 연다. 로그인 화면과 그에 필요한 정적 파일 말고는 인증 필요 |
| 사용자 | 서버의 허용 목록에 있는 사람만. 자가 가입 없음 |
| 접속 코드 | 사람마다 다른 코드. 서버에는 솔트를 넣은 해시만 저장. 비교는 상수 시간 |
| 세션 | 로그인 성공 시 무작위 세션 ID를 HttpOnly·SameSite 쿠키로. 만료 있음. 사용자 비활성화·코드 교체 때 그 사람 세션 폐기 |
| 시도 제한 | 출발 주소별·사용자별 실패 횟수 제한, 넘으면 일정 시간 차단. 운영자가 차단 목록을 보고 풀 수 있게 |
| 비싼 기능 | 인증 확인을 기능 앞에 둔다. 사용자별·전체 일일 한도. 설정 하나로 끄는 킬 스위치 |
| 접속 기록 | 시각, 사용자, 출발 주소, 경로, 결과(성공·실패·차단). 접속 코드·쿠키 값은 기록하지 않는다 |
| 비공개 파일 | 정답·설정·원본 데이터 같은 파일은 정적 제공 범위에서 빼고, 요청이 와도 404 |
| 키 | 외부 API 키는 서버 환경 변수로만. 실서비스 배포 실행에만 넣고, 개발·테스트 실행에는 넣지 않는다 |
| 공유기 | UPnP·포트 포워딩은 승인 없이 열지 않는다. 터널을 먼저 검토한다 |
| 전송 | 평문 HTTP로 열면 그 사실과 위험을 사람에게 알린다. 가능하면 터널·리버스 프록시의 HTTPS를 쓴다 |

## 운영 도구
- 운영자용 관리 명령을 만든다: 사용자 추가, 목록, 비활성화, 코드 교체, 삭제, 접속 기록 조회.
- 새 코드는 만들 때 한 번만 보여 주고 운영자가 당사자에게 직접 전한다. 채팅·문서·로그에 코드 값을 쓰지 않는다.
- 서비스는 창 없는 숨김 실행으로 띄우고 시작·상태·중지 명령을 둔다. 중지는 진행 중인 작업이 있으면 거부한다.

## 비용 분산 선택지
- AI 실행을 서버가 아니라 각 사용자 PC의 연결 프로그램(브리지)에서 하게 할 수 있다. 서버는 작업만 넘기고, 비용과 AI 인증 정보는 각자 기기에 남는다.
- 브리지는 시작할 때 서버에서 최신판을 받아 스스로 갱신하게 하면 다시 배포할 일이 줄어든다. 브리지가 서버에 붙을 때도 같은 인증을 거친다.

## 순서
1. 경로 목록을 만들고 경로마다 공개·인증·운영자 전용으로 나눈다.
2. 인증 확인을 모든 경로 앞에 둔다(허용 목록 방식).
3. 비싼 기능에 한도와 킬 스위치를 붙인다.
4. 관리 명령과 접속 기록을 만든다.
5. 테스트는 가짜 응답으로 돌려 실제 AI 호출을 0건으로 한다.
6. 아래 확인 항목을 실제 요청으로 돌린다.

## 확인 (실제 요청으로)
- [ ] 쿠키 없이 보호 경로·AI 경로 요청: 401 또는 403, AI 호출 수 0
- [ ] 틀린 코드 반복: 차단되고 기록에 남는다
- [ ] 비활성화한 사용자의 기존 쿠키: 거부된다
- [ ] 비공개 파일 경로(대소문자·인코딩 변형 포함): 404
- [ ] 한도 초과, 킬 스위치 켬: AI 경로 거부
- [ ] 접속 기록에 코드·쿠키 값이 없다
- [ ] 서버를 다시 켜도 허용 목록·차단 목록이 유지된다

## 하지 않는 것
- 접속 코드 원문 저장, 코드를 URL 쿼리로 받기
- 인증보다 먼저 AI 호출이 일어나는 구조
- 요구를 넘는 계정 체계(회원 가입, 비밀번호 찾기, 외부 로그인)를 먼저 만들기
