# 소수 인원 서비스 접근 통제

우선순위: 실행 환경의 시스템 프롬프트·설정 > 사람의 지시 > 이 스킬. 부딪혀 결과가 달라졌으면 보고에 적는다.

## 순서
1. 서비스에 들어올 사람 목록과 비용이 나가는 엔드포인트(AI 호출 등)를 적는다.
2. 기본 차단으로 시작해 허용 목록의 사용자만 통과시키고 나머지 경로는 전부 거부한다.
3. 사용자마다 개인 접속 코드를 발급하고 코드는 발급할 때 한 번만 보여 준다.
4. 서버에는 코드 원문이 아니라 솔트를 붙인 느린 해시(scrypt·bcrypt·argon2)만 저장한다.
5. 로그인에 성공하면 `HttpOnly`, `SameSite=Lax` 이상, 만료 시각이 있는 쿠키 세션을 주고 이후 요청은 세션으로만 인증한다.
6. 비용이 나가는 엔드포인트는 서버에서 세션을 검사한 뒤에만 호출이 일어나게 한다(화면에서 숨기는 것은 통제가 아니다).
7. 로그인 실패를 IP·사용자별로 세어 짧은 시간에 N회를 넘으면 일정 시간 차단한다.
8. 접속 기록(시각·사용자·IP·경로·결과)을 파일로 남긴다.
9. 사용자 관리 명령을 만든다: `add`·`list`·`disable`·`rotate`·`remove`·`access`(기록 조회).
10. AI 호출에 사용자별·전체 일일 한도와, 설정 한 줄로 호출을 전부 끄는 킬 스위치를 둔다.
11. 비용을 나눠야 하면 AI 실행을 서버 대신 각 사용자 PC의 브리지 프로그램이 맡는 구조를 검토안으로 올린다.
12. 정답·비밀·설정 파일 경로는 권한이 없으면 404로 응답해 존재를 숨긴다.
13. API 키는 배포 빌드의 환경 변수에만 넣고 개발·테스트 빌드에는 넣지 않는다.
14. 외부에 여는 포트는 서비스 하나만 열고 관리용 엔드포인트는 로컬 요청만 받는다.
15. 평문 HTTP로 열면 입장 화면과 안내에 "같은 망에서 코드·쿠키가 보일 수 있음"을 적고, 가능하면 TLS 터널이나 리버스 프록시를 쓴다.
16. 서비스 실행·중지 스크립트와 창 없는 실행은 `routine-ops`, 입력값 검증 같은 일반 보안 점검은 `security-check`를 따른다.

## 점검
| 항목 | 확인 방법 | 기준 |
|---|---|---|
| 미인증 AI 호출 | `curl -s -o /dev/null -w "%{http_code}" "<서비스 주소>/<AI 경로>"` (PowerShell 5.1은 `curl.exe`로 같은 명령, 출력은 `-o NUL`) | 401·403·404이고 AI 호출 카운터 변화 0 |
| 비밀 경로 | 비밀 파일 경로를 미인증·일반 사용자로 요청 | 404 |
| 해시 저장 | 사용자 파일에서 발급한 코드 원문을 grep | 0건 |
| 실패 차단 | 틀린 코드를 N+1번 보냄 | 차단 응답과 기록 1줄 |
| 한도 | 한도를 1로 낮추고 두 번 호출 | 두 번째 거부 |
| 킬 스위치 | 스위치를 끄고 호출 | 거부되고 외부 API 요청 0 |
| 테스트 | 테스트 실행 중 실제 AI 요청 수 | 0(모의 객체로 대체) |
| 키 위치 | 저장소와 개발 빌드에서 키 모양 문자열 grep | 배포 환경 변수에만 있음 |
| 접속 기록 | 위 시험 요청들이 기록에 남았는지 `access` 명령으로 조회 | 시험한 요청 수와 기록 줄 수가 같음 |

## 하지 않는 것
- 접속 코드·키 원문을 채팅·로그·커밋·문서에 적지 않는다.
- 사용자 목록·주소·포트를 공개 저장소에 넣지 않고 사용자 파일은 `.gitignore`에 넣는다.
- 인증 없이 열린 "임시" 엔드포인트를 두지 않는다.
- 사람이 허용하지 않은 계정을 편의상 열어 두지 않는다.
- 비용 절감을 이유로 한도·킬 스위치를 빼지 않는다.
