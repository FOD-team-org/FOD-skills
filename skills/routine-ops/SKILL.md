# 정기 루틴 운영

우선순위: 실행 환경의 시스템 프롬프트·설정 > 사람의 지시 > 이 스킬. 부딪혀 결과가 달라졌으면 보고에 적는다.

## 순서
### 평소
1. 루틴을 등록하거나 바꾼 날에는 등록 목록 출력(이름·일정·모델·상태)을 날짜 붙은 파일로 저장한다.
2. 루틴 본문 폴더와 등록부 파일을 함께 날짜 붙은 백업 폴더로 복사한다(본문에는 일정이 없고 등록부에만 있는 구조가 있다).
3. 루틴 일정은 문서에 적힌 값이 아니라 실제 등록값을 정본으로 삼는다.
4. 루틴마다 마지막 실행 시각을 일정과 대조해 한 주기 넘게 실행이 없으면 멈춤으로 본다.
   - Windows: `Get-ScheduledTask | Get-ScheduledTaskInfo | Select-Object TaskName,LastRunTime,LastTaskResult,NextRunTime`
   - macOS: `launchctl print gui/$(id -u)/<label>`의 마지막 종료 코드와 `ls -l <로그 파일>`의 수정 시각
   - 에이전트 루틴: 실행 세션 기록을 루틴 이름별로 세어 마지막 날짜를 본다.
5. 멈춘 루틴은 고치기 전에 일부러 끈 것인지 사람에게 묻는다.

### 등록부가 사라졌을 때
1. 남아 있는 루틴 본문 폴더를 통째로 먼저 백업한다.
2. 과거 세션 기록에서 가장 최근 목록 출력을 grep해 일정·모델을 복원한다(다음 실행 시각 같은 필드 이름으로 찾는다).
3. 반복 루틴만 같은 이름·같은 일정으로, 프롬프트는 자리표시로 다시 등록한다.
4. 백업한 본문 파일을 바이트 그대로 덮어쓰고 해시를 대조한다(`Get-FileHash <파일>` / `shasum -a 256 <파일>`).
5. 목록 명령으로 개수·일정·상태를 복원 전 기록과 대조한다.
6. 도구 승인이 초기화됐을 수 있으니 게시 루틴은 사람이 "지금 실행"으로 한 번 돌려 권한을 승인하게 안내한다.

## 점검
| 항목 | 기준 |
|---|---|
| 1회성 루틴 | 이미 실행된 1회성 작업은 다시 등록하지 않고 본문만 보관한다(다시 게시될 위험) |
| 창 없는 실행(Windows 스케줄러) | `wscript.exe //B <래퍼.vbs> <원래 .bat>`로 등록하고 래퍼는 `WScript.Shell`의 `Run 명령, 0, False`로 띄운다 |
| 창 없는 실행(Windows 파이썬 자식) | `creationflags=subprocess.CREATE_NO_WINDOW`를 쓴다(`DETACHED_PROCESS`는 새 콘솔 창을 띄운다) |
| 창 없는 실행(macOS) | `~/Library/LaunchAgents`의 plist로 등록하고 출력은 `StandardOutPath` 파일로 받는다 |
| 상시 서비스 | `start`·`status`·`stop` 스크립트를 두고 `stop`은 진행 중 작업이 있으면 거부한다 |
| 숨김 작업 진단 | 새벽에 도는 `wscript`·`python` 프로세스는 등록 작업 목록과 먼저 대조하고 이상 프로세스로 단정하지 않는다 |
| 낡아 보이는 작업 | 끄거나 지우기 전에 그 출력 파일을 읽는 다른 루틴·스크립트를 grep한다 |
| 경로 이동 | 스크립트를 옮기면 작업 인자와 시작 위치(Start In)를 같이 고치고 다음 실행 결과를 확인한다 |
| 규칙 변경 뒤 | 바꾼 규칙이 다른 루틴의 가드와 부딪히지 않는지 각 루틴 본문을 grep한다 |
| 헤드리스 실행 | `claude -p`로 도는 루틴은 `--disallowedTools "Agent,Task"`로 하위 위임을 막는다 |
| 루틴 안 하위 에이전트 | 루틴 안에서는 하위 에이전트를 띄우지 않는다(교착 사례) |
| 이어서 실행 | 중단된 작업을 이어갈 때는 상태 파일을 근거로 재개한다 |
| 기기 이전 | 다른 기기로 옮긴 루틴은 원래 기기에서 끄고 목록에 적는다(`cross-device-handoff`) |

## 하지 않는 것
- 루틴의 모델·추론 강도·일정은 사람 요청 없이 바꾸지 않는다.
- 모델 같은 설정은 등록부를 고치기보다 앱 UI로 바꾸는 단계를 `user-task-guide` 형식으로 안내하는 편을 먼저 고른다.
- 등록부 JSON을 직접 고쳐야 하면 백업을 먼저 하고 diff에 대상 줄만 바뀌었는지 확인한다.
- 권한 시스템이나 분류기가 거부한 우회(앱 내부 역공학 등)를 다시 시도하지 않고 멈춰 보고한다.
- 지표를 읽는 루틴이 운영 규칙 문서를 판정 없이 바로 고치게 만들지 않는다(`performance-insights`).
