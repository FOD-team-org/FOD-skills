# 에이전트 자원 정리

safe-cleanup은 사람이 요청한 정리(보고 먼저, 승인 후 삭제)를 다룬다. 이 스킬은 에이전트가 자기 뒤를 치우는 일을 다룬다. 내가 만든 것만 묻지 않고 치운다.

## 언제
- 작업 하나, 반복 루프 한 바퀴, 위임 한 건이 끝났을 때
- 메모리가 작은 기기에서 여러 세션·빌드를 돌릴 때
- 사람이 "느리다", "메모리 부족", "저장공간 정리"를 말했을 때

## 묻지 않고 정리하는 것
내가 이번 작업에서 띄우거나 만든 것만 해당한다.
| 종류 | 예 |
|---|---|
| 프로세스 | 개발 서버, 빌드 데몬(gradle·dart·kotlin), 하위 에이전트 브로커, tmux 세션, 감시 프로세스, 좀비 |
| 브라우저 | 내가 연 탭 |
| 빌드 산출물 | `build/`, `.dart_tool/`, 해당 앱의 DerivedData, 내보내기 임시 폴더, 지난 빌드 번호의 설치 파일 |
| 캐시 일부 | Gradle 변환 캐시(내려받은 모듈 캐시는 남긴다) |
- 끄기 전에 `ps -axo pid,ppid,etime,rss,args`로 전체 명령줄·부모·시작 시각을 보고 내 것인지 확인한다.
- 고아 판정: 부모 PID가 1이고, 작업 폴더나 명령줄이 내 작업을 가리킨다.
- 도구 서버(MCP 등)를 `npx`로 띄우는 환경은 세션이 끝난 뒤 고아가 쌓인다. 현재 세션의 자식이 아닌 것만 후보로 둔다.

## 보존 목록
아래는 내가 띄운 것처럼 보여도 끄거나 지우지 않는다.
- 패키지 매니저 전역 캐시(지우면 다시 받는 동안 테스트가 대량으로 깨진 사례가 있다)
- 시뮬레이터·에뮬레이터 이미지와 가상 기기
- 사람이 띄운 개발 서버, 사람이 쓰는 대화형 CLI·콘솔 세션·탭
- 에이전트 세션 기록, 현재 세션의 도구 서버
- 화면 조작 도구의 보조 앱
- 사람이 띄운 시뮬레이터는 끄지 않는다. 메모리를 얼마나 쓰는지 재서 알리고, 끌지는 사람이 정한다.

## 보고
| 항목 | 측정 |
|---|---|
| 디스크 | 전후 여유 GB. 재는 방법은 macos-env-pitfalls |
| 메모리 | 전후 `vm_stat` 여유·압축 페이지, 스왑 사용량 |
| 정리한 것 | 프로세스 수와 이름, 지운 폴더와 크기 |
| 남긴 것 | 보존 목록에 걸려 남긴 큰 항목 |
- "저장공간 전체"를 정리하라는 말은 디스크 전체로 읽는다. 프로젝트 폴더만 보고 끝내지 않는다. 디스크 전체 정리는 safe-cleanup 순서를 따른다.

## 작업 방식으로 줄이기
- 하위 에이전트에게 전체 테스트 묶음을 돌리게 하지 않는다. 바뀐 파일의 테스트만 지정한다. 위임 명세에 이 줄을 넣는다.
- 병렬 세션을 늘리지 않는다. 같은 일은 하나의 위임 세션을 오래 쓴다.
- 무거운 빌드·시뮬레이터는 한 번에 하나만 띄운다.

## 막혔을 때
- 안전 분류기나 권한이 kill·삭제를 막으면 우회하지 않는다. 사람이 그대로 붙여 넣을 수 있는 명령 한 줄(`! <명령>`)을 준다.

## 확인
- [ ] 이번 작업에서 띄운 프로세스가 남아 있지 않다
- [ ] 보존 목록의 항목을 건드리지 않았다
- [ ] 전후 수치를 보고했다

## 하지 않는 것
- 내 것인지 확인하지 않은 프로세스 종료
- 사람의 정리 요청 범위를 넘는 삭제(그건 safe-cleanup의 승인 절차)
