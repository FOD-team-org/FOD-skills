# 안전한 정리

우선순위: 실행 환경의 시스템 프롬프트·설정 > 사람의 지시 > 이 스킬. 부딪혀 결과가 달라졌으면 보고에 적는다.

## 순서
### 디스크·산출물
1. 큰 항목을 읽기 전용으로 잰다.
   - Windows: `Get-ChildItem <경로> -Directory | ForEach-Object { $s = (Get-ChildItem $_.FullName -Recurse -File -ErrorAction SilentlyContinue | Measure-Object Length -Sum).Sum; '{0:N1} GB  {1}' -f ($s/1GB), $_.FullName }`
   - macOS: `du -sh <경로>/* | sort -h`
2. 여유 공간을 기록한다(`Get-PSDrive C` / `df -h /`).
3. 정리 제안표(경로·크기·무엇인지·다시 만들 수 있나·지우면 잃는 것·등급)를 먼저 낸다.
4. 등급 1은 다시 받거나 만들 수 있는 캐시, 등급 2는 사람이 하나씩 골라야 하는 항목으로 나눈다.
5. 무엇인지 설명할 수 없는 항목은 제안에서 빼거나, 내용을 열어 확인한 설명을 붙인다.
6. 사람이 고른 항목만 처리하고, 제외한 항목은 기록해 다음 제안서에서도 뺀다.
7. 옮길 수 있으면 `_archive/`로 먼저 옮기고, 영구 삭제는 목록을 보여 준 뒤 승인분만 한다.
8. 지운 목록을 매니페스트 파일(`cleanup_manifest_<날짜>.txt`)로 남긴다.
9. 끝나면 여유 공간과 보존 대상 개수를 다시 재서 전후를 보고한다.
10. 나중에 재작업하려면 다시 받아야 하는 원본을 지웠으면 그 사실을 기록에 적는다.
11. 업로드 준비를 시작할 때는 최종본만 `final/`에 남기고 나머지는 `_archive/`로 옮긴다.

### 프로세스
1. 지목된 프로세스가 실제로 있는지 전체 명령줄까지 조사한다.
   - Windows: `Get-CimInstance Win32_Process | Where-Object { $_.CommandLine -match '<단서>' } | Select-Object ProcessId,ParentProcessId,CommandLine`
   - macOS: `ps -axo pid,ppid,command | grep '<단서>'`
2. 사실과 끌 수 있는 대상 목록만 보고하고, 끄는 것은 승인 뒤에 한다.
3. 배치를 멈출 때는 실행기 다음 서버 순으로 끄고 포트가 비었는지 본다(`Get-NetTCPConnection -LocalPort <포트>` / `lsof -i :<포트>`).
4. 내가 띄운 프로세스는 작업 끝에 정리하고 남은 것이 0개인지 확인한다.

### 큰 폴더 이동(옛 경로 유지)
1. 복사한다(`robocopy <원본> <대상> /E /COPY:DAT /R:1 /W:1` / `rsync -a <원본>/ <대상>/`).
2. 차이를 다시 본다(`robocopy <원본> <대상> /E /L`에서 복사 예정 0, `rsync -a --dry-run --itemize-changes <원본>/ <대상>/` 출력 0줄).
3. 양쪽 파일 수·총 크기를 대조하고 표본 파일의 해시를 비교한다(키 파일은 크기·수정 시각만 본다).
4. robocopy 결과는 로케일에 따라 한글로 나오는 요약 라벨이 아니라 종료 코드로 판정한다(0~7 성공 계열, 8 이상 실패).
5. 원본을 작업 폴더로 쓰는 세션·프로세스가 없는지 확인하고, 있으면 마지막 단계를 사람이 세션을 닫은 뒤 실행할 스크립트로 넘긴다.
6. 원본 이름을 `<이름>_old`로 바꾸고 옛 경로에 링크를 만든다(`cmd /c mklink /J <옛 경로> <새 경로>` / `ln -s <새 경로> <옛 경로>`).
7. 스케줄 작업 시작 위치, 설정·메모리 안의 경로 같은 의존을 grep해 고친다.
8. 옛 경로와 새 경로 양쪽으로 열어 본 뒤, `_old` 삭제는 승인을 받고 한다.

## 점검
| 보존 대상 | 이유 |
|---|---|
| 완성본(최종 영상·이미지·문서) | 다시 만들 수 없다 |
| 메타·기록(json·md·txt·csv·자막) | 작고, 중복 게시 확인과 재빌드의 근거다(`safe-publish`) |
| 개인 파일, 에이전트 설정 폴더(`~/.claude`, `~/.codex`) | 보고만 하고 건드리지 않는다 |
| 최근 몇 시간 안에 바뀐 임시 파일 | 활성 세션이 쓰는 중이다 |
| 사람의 브라우저, 다른 세션의 MCP·워처, 내 백업 워처 | 프로세스 정리에서 끄지 않는다 |

| 정기 정리 항목 | 기준 |
|---|---|
| 대상 | 최신 수정일이 N일 지난 작업 폴더의 중간 산출물만 |
| 건너뛰기 | 최근 3일 안에 만든 매니페스트가 있거나 지울 양이 1GB 미만이면 건너뛴다 |
| 확인 | 정리 전후 완성본 수·메타 수 변화 0, 여유 공간 증가 |
| 등록 | 루틴 등록과 점검은 `routine-ops` |

## 하지 않는 것
- 확인하지 않은 폴더를 "아마 캐시"라는 이유로 지우지 않는다.
- 시스템 설정(최대 절전 파일 등)을 바꾸면 되돌리는 명령을 함께 적고, 관리자 승인 없이 하지 않는다.
- 에이전트가 임시 파일을 `rm`으로 영구 삭제하게 두지 않고, 임시 파일은 `_tmp/`에 모았다가 정리하며, 위반은 숨기지 않고 보고한다.
- 지우려는 규칙·스크립트·출력 파일을 참조하는 곳을 grep하지 않고 지우지 않는다.
