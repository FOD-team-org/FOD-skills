# 콘솔 화면 자동 조작

## 언제
- 사람이 콘솔 화면에서 값을 바꾸거나 읽어 오라고 했을 때
- API가 없거나 API로 안 되는 설정(약관 동의 뒤 화면, 심사 메모, 일부 신고 항목)을 다룰 때

## 도구 고르기
1. 공식 API나 CLI가 있으면 그것을 쓴다. 화면 조작은 마지막 수단이다.
2. 화면 조작 도구는 사람이 정한 한 가지만 쓴다. 막혔다고 다른 브라우저 도구로 바꾸지 않는다. 같은 로그인 상태를 두 도구가 다루면 세션이 꼬인다.
3. 사람이 쓰는 앱을 대신 띄우지 않는다. 도구가 "브라우저 없음"처럼 보조 앱이 꺼졌다고 알리면 그 보조 앱만 켠다.

## 사전 점검
- 화면이 잠겨 있으면 시작하지 않는다. 별도 종료 코드로 끝내고 사람에게 알린다(macos-env-pitfalls).
- 자동 조작 도구가 앱마다 권한 승인을 요구하면, 사람이 대화형으로 한 번 승인해 둔다. 무인 실행은 승인 창을 누를 수 없다.
- 처음 쓰는 콘솔은 읽기만 하는 짧은 시험 실행으로 로그인 상태와 화면 구조를 먼저 본다.

## 실행
- 콘솔 작업 하나에 스크립트 하나, 로그 파일 하나를 둔다. 로그 줄에 표시를 단다: ✅ 완료, ⛔ 실패·거절, 🔒 로그인·권한 필요.
- 읽기 작업과 쓰기 작업을 나눈다. 읽기로 현재 값을 먼저 받아 두고, 쓰기는 바꿀 값만 지정해 따로 돌린다.
- 위임할 때 표준 입력을 닫는다(`< /dev/null`). 시도 횟수는 1회, 거절되면 멈추고 화면을 캡처해 보고한다.
- 파일 선택 창은 화면 캡처로 위치를 찾고, 경로를 넣은 뒤 Return으로 닫는다.
- 내려받은 키 파일은 권한 0600으로 정해진 폴더에 둔다. 내용은 열지 않는다.

## 하지 않는 것
아래 화면이 나오면 입력하지 않고 🔒로 기록하고 멈춘다.
- 비밀번호, 2단계 인증 코드, CAPTCHA
- 카드·계좌·세금 정보
- 약관·계약 동의 버튼(사람이 그 건을 명시 승인했을 때만)
- 심사 제출, 삭제, 공개 전환
- 로그인 화면이 나오면 로그인을 시도하지 않는다. 사람이 로그인한 뒤 다시 돌린다.

## 확인
- 저장한 값은 페이지를 다시 열어 화면에서 읽어 확인한다. URL이 바뀐 것은 페이지가 열린 증거가 아니다.
- "제출함"과 "승인됨"을 나눠 보고한다. 심사·검토가 남아 있으면 그 상태를 그대로 적는다.
- 끝나면 내가 연 탭만 닫는다. 사람이 연 탭과 콘솔 세션은 그대로 둔다.

## 막혔을 때
- 같은 동작을 다른 도구로 반복 시도하지 않는다.
- 사람이 해야 할 동작 하나(로그인, 권한 허용, 버튼 하나)를 user-task-guide 형식으로 정확히 요청하고, 끝나면 이어서 돌린다.
