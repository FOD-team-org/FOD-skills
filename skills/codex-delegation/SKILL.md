# Codex에 맡기기

## 언제
- 사람이 Codex와 협업하거나 교차 검수하라고 했을 때.
- 대량 조사·이미지 생성·계정 화면 조작처럼 메인 토큰을 아낄 일.
- 다른 모델 계열의 두 번째 의견이 필요할 때(multi-ai-review와 함께).

## 준비
- 실행 파일 위치·버전·모델 이름은 환경에 맞게 확인한다. 모델 이름은 설정 파일이나 공식 목록에서 확인하고 짐작해 쓰지 않는다. 짐작한 이름은 오류가 난다.
- 사람이 모델·추론 강도를 지정했으면 그대로 쓴다. 보고에는 Codex의 자기 표기가 아니라 실제로 넘긴 인자를 적는다.
- 처음 쓰는 환경이면 인자 전달 시험을 한 번 한다. 따옴표·특수문자를 넣고 그대로 돌려받는지 본다.

## 브리프와 호출
1. 지시 본문은 UTF-8 브리프 파일로 쓴다. 명령줄에는 "이 파일을 읽고 따르라"는 짧은 ASCII 문장만 넣는다. 긴 인라인 지시와 한글 따옴표는 깨진다.
2. 브리프를 쓴 뒤 파일이 실제로 있고 내용이 맞는지 확인하고 호출한다.
3. 브리프에 넣는 것: 목적, 먼저 읽을 파일, 할 일, 금지(키·인증 파일 읽기, 범위 밖 쓰기, 게시), 산출물 경로, 결과 형식.
4. 호출 기본형: `codex exec` + 작업 폴더 지정 + 샌드박스 수준 명시(검수는 읽기 전용) + 결과 파일 출력 옵션 + 표준 입력 닫기(`< /dev/null`). 표준 입력을 안 닫으면 끝없이 기다린다.
5. 오래 걸리는 호출은 백그라운드로 띄우고, 완료 알림 뒤 결과 파일을 읽는다.
6. 무거운 요청은 쪼갠다. 다음 라운드는 바뀐 부분만 보낸다.
7. 샌드박스가 막는 일(특정 경로 쓰기, 네트워크 측정)은 메인 셸이나 다른 실행자로 돌린다.
8. 브리프에 "전체 테스트 묶음을 돌리지 않는다. 바뀐 파일의 테스트만 돌린다"를 넣는다. 같은 일에 Codex 세션을 여러 개 띄우지 않고, 한 세션을 이어 쓴다.
9. 샌드박스 안에서 테스트가 권한 오류로 안 돌면 통과로 쓰지 말고 "실행 못 함"으로 보고하게 한다(scoped-change-verification).
10. 화면·콘솔 조작은 console-cua-automation을 따른다.

## 용도별로 더할 것
| 용도 | 브리프에 더할 것 |
|---|---|
| 교차 검수 | 검수 대상 파일, 볼 관점(설계·로직·보안), 지적마다 근거 위치, 고치지 말고 지적만 |
| 구현 | 수용 기준, 건드릴 파일, 검증 명령. delegation-loop의 명세 틀을 따른다 |
| 이미지 생성 | 비대화형, 생성 도구 정확히 1회, 다른 스크립트로 대체 금지, 파일 이동·추가 생성 금지, 저장 경로만 답. 참조 이미지는 절대 경로, 용도·크기·비율 명시, 지시하지 않은 소품 금지 |
| 화면·계정 조작 | 바꿀 값, 시도 1회, 거절되면 멈추고 보고, 비밀번호·2단계 인증은 입력하지 않음, 결과 화면 캡처 |
- 이미지 생성은 순차로 돌린다. 채택한 대표 이미지를 다음 호출의 스타일 참조로 쓴다. 기각본도 보관한다.
- 계정 이름 같은 값은 플랫폼 규칙(글자 수·특수문자)을 먼저 확인한다. 재시도를 반복하면 계정이 잠길 수 있다.

## 회수와 검수
- 완료 기준은 디스크의 산출물이다. 로그가 끊겨도 산출물·프로세스·CPU 시간으로 생존을 판단한다.
- 결과 파일이 비었으면 Codex 세션 기록 파일에서 회수한다.
- Codex 지적마다 채택·기각과 이유를 작업 기록에 남긴다. 교차 검수를 정한 작업이면 빠뜨리지 않는다.
- 시각·픽셀 결과는 Codex 보고를 믿지 않고 메인이 본다. 브리프에 "검증을 통과시키려고 결과물을 직접 고치지 않는다"를 넣는다.
- 돌려받은 문구에서 따옴표 같은 기호가 빠졌는지 보고, 조립할 때 복원한다.
- 오래 돈 Codex 프로세스는 사람이 띄운 것일 수 있다. 시작 시각을 보고 내가 띄운 고아 프로세스만 정리한다.

## 하지 않는 것
- 취향·채택 판정(go/no-go)을 맡기지 않는다. 대량 생성, 반론, 사실 확인을 맡긴다.
- 메인이 자기 브라우저 도구로 계정 화면을 반복 시도하지 않는다.
- 사람이 Codex에 맡기지 말라고 한 영역은 맡기지 않는다.
