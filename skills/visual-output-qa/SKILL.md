# 시각 결과물 검수

시각 판정은 메인이 결과 이미지를 직접 열어 본다. 하위 에이전트와 검사 스크립트는 수치와 경로만 낸다.

## 언제
- 렌더한 영상, 카드, 썸네일, 생성 이미지를 채택하거나 게시하기 전
- 빌드 스펙에 크롭·가림·블러 좌표를 적어야 할 때
- 디자인 시안을 앱·웹 화면에 반영한 뒤

## 순서
1. 프레임을 뽑는다. 전체를 일정 간격으로 훑는 시트, 대표 프레임, 파트 경계 앞뒤 연속 프레임 타일. 경계 타일은 시각(초)이 아니라 프레임 번호로 뽑는다.
2. 축소 시트로 먼저 훑고, 의심 구간은 원본 크기로 연다. 화면 가장자리·하단·작은 글자는 원본 크기나 2배 확대로 본다.
3. 아래 "볼 것" 표를 기준으로 메인이 직접 본다. 본 프레임 목록과 결과를 기록한다.
4. 기계 검사를 쓸 때는 먼저 양성 대조(일부러 결함을 넣은 입력)와 음성 대조(정상 입력)로 검사기가 실제로 잡는지 확인한다. 대조 없이 정한 임계값은 쓰지 않는다.
5. 검사 영역은 결함이 나오는 위치로 좁힌다(예: 하단 띠). 화면 전체에 걸면 조명·간판 때문에 오탐이 생긴다. 길게 이어지는 검출은 배경일 가능성이 크고, 몇 프레임짜리 짧은 검출을 잘라 직접 본다.
6. 결정성이 의심되면 같은 인자로 두 번 빌드해 해시를 비교한다. "비결정성", "코덱 탓" 같은 해명은 이 재현으로 검증한다.
7. 같은 사건의 다른 소스(재방송·다른 각도)가 있으면 시트를 비교한다. 더 잘 보이는 화면이 있을 수 있다.
8. 채택·반려와 사유를 판정 원장에 적는다.

## 볼 것
| 항목 | 기준 |
|---|---|
| 글자 | 잘림·오탈자·글자 뭉침·작은 숫자 깨짐이 없다. 코드포인트 검사는 뭉침을 못 잡으니 확대해서 본다 |
| 문장과 화면 | 화면이 문장 내용과 맞는다. 비난·혐의 문장 위에 그 행위자로 오인될 사람 컷(뒷모습 포함)을 두지 않고 사물·풍경 컷을 쓴다 |
| 소스 잔재 | 원본의 로고·레이블·자막 띠·장식 효과 잔상·양옆 필러 띠가 남지 않는다. 일부 구간에만 나타나는 레이블이 있으니 사용 구간 전체를 훑는다 |
| 제3자 정보 | 간판·현수막·차량의 전화번호, 번호판, 관련 없는 사람 얼굴을 원본 크기로 확인하고 국소 블러(움직이면 추적)한다 |
| 경계 | 파트 경계 앞뒤에 이전 장면 잔상·번쩍임 프레임이 없다 |
| 가림 영역 | 플랫폼 UI가 덮는 영역에 핵심 글자·물체가 없다 |

## 크롭·가림 좌표 실측
- 좌표는 메인이 소스 프레임에서 잰다. 장면표의 추정값, 관찰 메모의 대략값을 그대로 넘기지 않는다.
- 소스 프레임에 격자를 덧그려 경계를 읽고, 해당 시점(줌·팬 이후) 프레임에서 잰다.
- 텍스트 카드는 글자 영역 경계 상자를 재고 여백을 두어 크롭한다. 크롭의 네 변은 글줄 사이 빈 줄에 둔다. 따옴표 자막이 여러 개면 각각 잰다.
- 줌·팬이 있는 문서 컷은 줌 시작 시점을 재고 그 이전까지만 쓴다.
- 세로로 찍은 소스는 실제 영상이 차지하는 폭을 재고, 그에 맞는 프레이밍을 고른다.
- 우선순위는 행위자·핵심 물체가 먼저, 방해 요소 회피가 다음이다. 레이블이 글줄과 겹치면 크롭을 줄이기보다 사용 구간 시작점을 옮긴다.
- 실측값과 근거 프레임 경로를 스펙에 함께 적는다.

## 생성 이미지
- 점검: 신체 결함, 지시하지 않은 사람·소품, 얼굴 동일성, 글자 깨짐, 스펙(의상·장소·구도) 불일치, 조명 물리.
- 기각 사유는 스펙과 대조한 뒤 확정한다. 스펙에 있던 소품이면 "비율 오류"이지 단순 결함이 아니다.
- 얼굴이 일부만 보여 동일성을 판단하기 어려우면 통과가 아니라 "판정 필요"로 넘기고 기준 얼굴과의 대조 시트를 붙인다.
- 재생성은 사람이 정한 횟수까지 자동으로 하고, 시드는 이전과 겹치지 않는 대역에서 고른다. 그 뒤에도 실패하면 표시해 보고한다.
- 위임받은 실행자는 "의심·보류"까지만 표시한다. 채택·기각은 사람 또는 메인이 한다. 탈락본도 지우지 않는다.
- 수치 지표(밝기 등)는 참고만 한다. 판정은 눈으로 한다.
- 앱 아이콘·스토어 이미지 같은 최종 자산은 코드로 그린 도형으로 만들지 않는다. 이미지 생성 도구로 만들고, 경쟁 앱 자산과 실제 크기로 한 장에 놓고 비교한다. 같은 개발자의 앱끼리도 시각 정체성을 다르게 한다.
- 스토어 스크린샷은 사용이 진행된 상태의 시연 데이터와 서로 다른 구도로 만든다. 글자가 든 이미지는 큰 해상도로 만든 뒤 줄이고, 한글 글자 깨짐을 확대해 본다.

## 디자인 시안 충실도
- 시안 대비 화면별 차이표를 만든다. 차이마다 고치거나 사유를 적는다.
- 시안과 시뮬레이터·실기기 캡처를 한 장에 나란히 놓고 본다.
- 색 대비는 축소 화면이 아니라 확대 이미지에서 잰다.
- 기기 크기별로 넘침·잘림을 확인한다.
- 디자인 상수가 선언만 되고 쓰이지 않는지 실제 호출부까지 코드로 확인한다.
- 폐기된 테마의 잔재와 자산 크기 제한을 확인한다.

## 하지 않는 것
- 하위 에이전트의 "정상", "잘림 0" 보고를 근거로 채택하지 않는다.
- 위임 프롬프트에서 시각적 판단을 보고하라고 하지 않는다.
- 검사 통과를 위해 결과물 픽셀을 직접 칠하게 두지 않는다.
