# 속도 제한 조사

## 언제
- 여러 사이트·여러 영상의 정보를 모을 때(채널 스캔, 레퍼런스 수집, 자막·댓글 수집, 자료 조사).
- 이런 조사를 다른 에이전트에게 맡길 때.

## 순서
1. 공식 API가 있으면 그것부터 쓴다. 대량 조사는 공식 API로만 한다.
2. 브리프를 쓴다(아래 틀). 위임하면 브리프 파일을 넘긴다.
3. 처음 몇 건으로 시험해 파싱이 맞는지 확인한 뒤 나머지를 돌린다.
4. 결과를 감사한다: 링크·ID가 실제와 맞는지, 숫자 파싱(단위, 자릿수, 현지어 표기)이 맞는지 표본으로 확인한다.
5. 규칙 위반(상한 초과, 재시도 초과)이 있었으면 보고에 한 줄로 밝힌다.

## 브리프 틀
| 칸 | 쓰는 것 |
|---|---|
| 목적 | 무엇을 정하려는 조사인지, 조건(제작 방식, 예산) |
| 먼저 읽을 것 | README, 현재 후보 목록, 판정 기준, 측정 방법, 이미 확인한 자료(다시 조사하지 않음) |
| 속도 규칙 | 사이트당 동시 요청 1개, 병렬·스레드·백그라운드 금지, 요청 사이 간격, 전체 상한(검색 포함), 시간당 상한 |
| 차단 대응 | 403·429면 기다린 뒤 1회만 재시도. 한 사이트가 막히면 그 사이트만 멈춘다. 주요 플랫폼이 막히거나 여러 곳이 막히면 전체를 멈추고 보고 |
| 금지 | 로그인·쿠키·프록시로 우회, 크롤링 금지 문구가 있는 사이트 저장, 남의 저장소 코드 실행 |
| 캐시 | 받은 원문을 파일로 저장하고 다시 요청하지 않는다. 호출 로그(시각, URL, 결과 코드)를 남기고 다음 작업 전에 확인한다 |
| 결과 | 표 형식과 저장 위치 |
- 시작 기본값은 보수적으로 잡는다. 예: 동시 1개, 요청 간격 10초, 영상 다운로드는 시간당 10건 이하. 차단이 없을 때만 사람과 상의해 늘린다.

## 결과 표
| 항목 | 값 | 출처 URL | 확인 시각 | 원문 인용 |
|---|---|---|---|---|
- 날짜·장소·수치 문구는 출처 원문에서 직접 읽어 옮긴다.
- 확인 못 한 칸은 비우고 "미확인"으로 쓴다.

## 도구 사용
- 영상 메타데이터 다운로더는 한 건씩 실행한다. 여러 명령을 이어 붙여 한 번에 돌리지 않는다.
- 자막은 원어 트랙만 받는다. 자동 번역 자막 요청은 차단을 부른다.
- 내려받은 파일은 따로 만든 빈 폴더에 두고, 처리 스크립트는 다른 폴더에서 돌린다.
- 사용자 IP가 막히면 사람의 일상 사용(브라우저)까지 느려진다. 상한을 채우려고 간격을 줄이지 않는다.
- 한글 페이지나 콘솔 출력이 깨지면 UTF-8 파일로 저장해 읽는다.

## 확인
- 차단 없이 끝났거나, 차단 시점과 멈춘 범위가 보고에 있다.
- 감사 결과 틀린 숫자 0, 틀린 링크 0이다.
- 모든 값에 출처 URL과 확인 시각이 있다.

## 하지 않는 것
- 차단을 우회하지 않는다.
- 제목·설명란만 보고 내용을 단정하지 않는다. 인용은 자막 원문과 시각으로 대조한다.
