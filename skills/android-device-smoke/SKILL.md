# 안드로이드 실기기 스모크

## 언제
- 새 빌드를 실기기에서 처음 확인할 때
- 에뮬레이터에서 안 보이는 문제(권한, 백그라운드 동작, 알림)를 볼 때

## 준비
- 무선 디버깅은 사람이 폰에서 페어링 코드와 연결 주소를 알려 준다. 코드·주소는 그 자리에서만 쓰고 문서·로그에 남기지 않는다.
- 시나리오 표를 먼저 쓴다: 단계, 조작, 기대 화면, 기대 로그.

## 순서
1. 연결: `adb pair`, `adb connect`, `adb devices`로 기기 상태가 device인지 본다.
2. 사람 사용 확인: 조작 전에 지금 포그라운드 앱과 화면 상태를 본다(`dumpsys activity`, `dumpsys window`, `dumpsys power`). 사람이 폰을 쓰는 중이면 멈추고 묻는다.
3. 설치 파일 대조: 설치할 APK의 SHA-256과 빌드 시각이 방금 빌드한 산출물과 같은지 본다. 백그라운드 빌드가 PATH 문제로 실패하고도 종료 코드 0을 낸 사례가 있다.
4. 설치: `adb install -r`. 한글 경로에서 실패하면 ASCII 경로로 복사해 설치한다. 설치 뒤 `dumpsys package <패키지>`의 versionCode와 설치 시각을 확인한다.
5. 로그: 실행 전에 `adb logcat -c`, 실행 중에는 앱 패키지·태그로 걸러 파일에 저장한다.
6. 화면 켜기와 실행: `input keyevent KEYCODE_WAKEUP`, 실행은 `am start` 또는 `monkey -p <패키지> 1`.
7. 단계마다 조작하고, 화면 전환을 기다린 뒤 캡처한다. 캡처는 기기에 `screencap -p /sdcard/<파일>`로 저장한 뒤 `adb pull`로 받는다. `exec-out`으로 바로 받으면 바이트가 섞인 사례가 있다. Git Bash에서는 `MSYS_NO_PATHCONV=1`을 붙인다.
8. 끝나면 기기에 남긴 캡처 파일을 지우고, 앱 상태를 원래대로 둔다.

## 판정
- 캡처는 메인(또는 사람)이 직접 열어 본다. 하위 에이전트의 "화면 정상" 보고는 판정으로 쓰지 않는다.
- 작은 글자·대비 문제는 축소본이 아니라 원본 크기로 본다.
- 로그에서 크래시(FATAL EXCEPTION, ANR)와 앱 태그 오류를 grep한다.

## 결과 표
| 단계 | 조작 | 기대 | 캡처 파일 | 로그 이상 | 판정(통과·실패·못 봄) |
|---|---|---|---|---|---|
- 표 위에 기기 모델, OS 버전, APK 해시, 설치 시각을 한 줄로 적는다.

## 확인
- [ ] 설치된 versionCode·설치 시각이 이번 빌드와 맞다
- [ ] 시나리오의 모든 단계에 캡처와 판정이 있다
- [ ] 크래시 grep 결과를 표에 적었다

## 하지 않는 것
- 사람이 폰을 쓰는 중에 설치·조작
- 해시 확인 없이 "최신 빌드 설치함" 보고
- 페어링 코드·기기 주소를 문서에 기록
