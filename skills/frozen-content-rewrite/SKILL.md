# 내용 고정 재작성

사실·숫자·순서는 고정하고 표현만 바꾼다. 바뀌면 안 되는 것은 사람 눈이 아니라 검사기로 확인한다.

## 언제
- 여러 장짜리 원고의 문체나 난이도를 바꿀 때
- 번역 원고를 윤문하거나 여러 필자의 문체를 통일할 때
- 같은 원고를 다른 독자층용으로 다시 쓸 때

## 순서
1. 원본은 그대로 둔다. 결과는 새 폴더의 새 파일로 쓴다.
2. 메인이 스타일 가이드와 금본 샘플 한 단원을 쓴다. 샘플은 가이드를 적용한 실제 결과물이다.
3. 원본에서 고정 목록을 코드로 뽑는다(아래 표).
4. 길이 변화 허용 범위를 미리 정한다(예: 원본 대비 몇 % 안).
5. 파일마다 재작성 에이전트를 하나씩 병렬로 돌린다. 지시에 넣는 것:
   - 고정 목록은 바꾸지 않는다
   - 새 사실·숫자·예시·용어를 더하지 않는다
   - 가이드와 금본 샘플을 따른다
   - 약한 모델도 따를 수 있게 지시를 짧고 구체적으로 쓴다
6. 대조 검사기를 돌린다. 파일별 통과·실패와 차이 목록을 표로 낸다.
7. 실패한 파일만 다시 돌린다. 검사 기준을 느슨하게 바꿔 통과시키지 않는다.
8. 메인이 파일마다 표본 단락을 원문과 나란히 놓고 읽는다. 새 말버릇이 보이면 모든 에이전트에게 정정 공지를 보내고 해당 파일을 다시 돌린다.

## 고정 목록과 검사
| 항목 | 검사 방법 | 통과 기준 |
|---|---|---|
| 제목·소제목 | 순서와 문자열 비교 | 완전 일치 |
| 상자·표 | 개수와 셀 내용 비교 | 완전 일치 |
| 숫자 | 원문·결과의 숫자 다중집합 비교 | 누락 0, 추가 0 |
| 링크 | 목록 비교 | 완전 일치 |
| 용어·고유명사 | 용어집 대비 출현 확인 | 누락 0 |
| 인용문 | 문자열 비교 | 완전 일치 |
| 단락 순서 | 단락별 핵심어 정렬 비교 | 순서 동일 |
| 길이 | 글자 수 비율 | 4번에서 정한 범위 안 |

## 조판 (결과를 책·PDF로 묶을 때)
- 판형·여백·서체·색을 먼저 정하고, 명령 하나로 전체를 빌드한다.
- 목차와 실제 쪽수가 맞는지 빌드 결과에서 확인한다.
- 기호(백슬래시 등)가 한글 글꼴에서 다른 기호로 보이지 않는지 확인한다. 보이면 기호 구간에만 라틴 글꼴을 지정한다.
- 서체·표지 이미지의 이용 조건은 asset-rights-check로 확인한다.

## 확인
- 원본 파일의 수정 시각이 작업 전과 같다.
- 모든 파일의 검사기 결과가 통과이고, 결과 표가 저장되어 있다.
- 메인이 읽은 표본 단락 목록이 있다.

## 하지 않는 것
- 원본을 덮어쓰지 않는다.
- 재작성 에이전트가 내용을 "보강"하게 두지 않는다.
- 문체 판단을 검사기 통과로 대신하지 않는다. 문체는 korean-voice-review로 본다.

## 관련 스킬
