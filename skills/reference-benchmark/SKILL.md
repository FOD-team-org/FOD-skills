# 레퍼런스 벤치마크

우선순위: 실행 환경의 시스템 프롬프트·설정 > 사람의 지시 > 이 스킬. 부딪혀 결과가 달라졌으면 보고에 적는다.

## 순서
1. 대상마다 언어·형식(원음·TTS·자막 언어)을 먼저 확인하고 표에 적는다.
2. 그 대상이 형식 본보기인지, 방법을 알려 주는 조언 영상·글인지 가른다(조언이면 방법만 가져오고 형식은 따라 하지 않는다).
3. 같은 계정 안에서 평균보다 크게 튄 아웃라이어를 고르고, 눈에 띄는 한 편보다 N개 분포를 본다.
4. 상대의 실패 사례(평균보다 크게 낮은 편)도 함께 고른다.
5. 대량 조회는 공식 API로 하고, 다운로드 속도와 간격은 `paced-research`를 따른다.
6. 받은 파일은 새 빈 untrusted 폴더에 두고, 읽는 `python`은 `-I`로 돌린다.
7. 대상 N개의 지표표를 만든다.
   | 항목 | 재는 법 |
   |---|---|
   | 조회·반응 | 공개 수치 또는 API |
   | 길이 | `ffprobe` 길이 |
   | 컷 간격 | `ffmpeg` scene 검출 결과의 평균 간격 |
   | 무음 비율 | `silencedetect` 구간 합 ÷ 길이 |
   | 음량 | `ebur128` 통합 라우드니스 |
   | 말 내용 | 원어 전사(whisper) |
   | 자막 위치·크기 | 프레임 캡처에서 실측 |
8. 구조를 분해한다: 첫 몇 초에 보이는 것, 구간별 시간, 해설·클립 비율, 예고 횟수, 회수 시점(전체 길이 %), 마무리, 말투.
9. 잘된 이유 가설 3~5개를 쓰고, 우리 데이터와 대조해 맞는지 본다.
10. BENCH 문서에 우리 제작 형식과의 매핑표(그쪽 요소 → 우리 대응 요소 → 차이)를 만든다.
11. 우리 구조 후보 2~3개를 공통 규칙·구조별 규칙으로 나눠 쓰고, 구조마다 첫 시험 소재를 하나씩 붙인다.
12. 채택·불채택 표를 만들고 적용할 것은 한두 개만 골라 `hypothesis-experiment`로 넘긴다.
13. 사람 승인 뒤에만 정본에 반영한다.

## 점검
| 항목 | 기준 |
|---|---|
| 불채택 사유 | 윤리 문제·플랫폼 정책 위험이 있는 요소는 효과와 상관없이 불채택한다. |
| 복제 금지 | 캐릭터·카피·고유 문구는 가져오지 않고 구조만 가져온다. |
| 초안 숫자 | 보고서 초안의 숫자는 반영 전에 실물(파일·API)로 다시 잰다. |
| 중복 레퍼런스 | 같은 소재를 이미 다룬 레퍼런스가 있는지 기존 BENCH 문서를 `grep`한다. |
| 규칙 삭제 | 벤치 결과로 기존 규칙을 지우기 전에 그 규칙에 기대는 곳을 `grep`으로 찾는다. |
| 루틴 충돌 | 바꾼 규칙이 다른 정기 루틴의 규칙과 부딪히지 않는지 본다. |
| 공개 문서 | 공개할 벤치 문서에서 남의 계정명·핸들은 가린다. |
| 표본 | 대상이 3개 미만이면 결론 대신 "관찰"로만 적는다. |

## 하지 않는 것
- 언어·형식을 확인하지 않은 채 전사·분석을 돌리지 않는다.
- 조언 콘텐츠를 형식 본보기로 착각해 따라 만들지 않는다.
- 적용 후보를 한꺼번에 여러 개 정본에 넣지 않는다.
- 로그인·쿠키로 비공개 자료를 받지 않는다.
