# 다른 기기로 넘기기

## 언제
- 같은 프로젝트를 다른 PC(다른 OS 포함)에서 이어 할 때
- 사람이 밖에서 폰으로 결과물을 봐야 할 때

## git 인계 순서
1. 넘길 저장소 목록을 만든다(코드, 문서, 설정 저장소).
2. 저장소마다 커밋 안 된 변경을 확인하고 커밋한다. 판단대기·작업 일지·runbook 같은 문서도 커밋한다.
3. 비밀값을 스캔한다. `.env`, 키·인증서·서명 파일, 토큰이 든 설정 파일이 추적 목록에 없는지 `git ls-files`와 패턴 grep으로 보고, `.gitignore`에 들어 있는지 확인한다.
4. push 전에 활성 git 계정과 원격 저장소 주인이 프로젝트에서 정한 계정인지 확인한다. 여러 계정을 쓰는 CLI는 다른 프로젝트 계정으로 바뀌어 있을 수 있다. 커밋 작성자도 본다.
5. push 후 원격 최신 커밋이 로컬과 같은지 확인한다.
6. 이미 push한 이력은 force push로 고치지 않는다. 사람이 승인했을 때만 한다.

## git으로 옮기지 않는 것
| 종류 | 옮기는 법 |
|---|---|
| 비밀값(.env, API 키, 인증서, 서명 키) | 사람이 안전한 경로로 직접 옮긴다. 채팅·문서에 값을 쓰지 않는다 |
| 로컬 DB·캐시·대용량 산출물 | 필요한 것만 목록에 올리고, 다시 만드는 명령을 함께 적는다 |
| 기기별 설정(경로·SDK 위치) | 새 기기에서 다시 설정하는 단계로 적는다 |
- 수동 이동 목록에는 파일 이름과 용도만 적고 값은 적지 않는다.
- 기기마다 다른 값(경로, 작업 ID, 계정 ID)은 코드에 박지 않고 환경 변수로 받는다. 다른 기기의 ID를 재사용하지 않는다.
- 실제 행동을 하는 기능(실주문, 발송, 게시, 예약 작업)은 새 기기에서 꺼진 상태로 시작하고, 확인한 뒤 하나씩 켠다.
- 지침 파일에 이전 OS 전용 규칙(셸, 경로, 인코딩)이 있으면 새 기기 OS에 맞는지 본다(windows-env-pitfalls, macos-env-pitfalls).

## 인계 문서 (저장소 안 한 파일)
- 지금 상태: 마지막으로 끝낸 일, 진행 중인 일, 막힌 일
- 새 기기 준비: 설치할 도구와 버전, 받을 저장소, 수동으로 옮길 파일
- 확인 명령: 빌드·테스트·실행 명령 한 줄씩과 기대 결과
- 다음 할 일: 우선순위 순서 목록
- 사람이 할 단계는 user-task-guide 형식으로 쓴다.
- 대화 맥락이 길어져 같은 기기에서 세션을 바꿀 때도 같은 형식의 인계 문서를 남긴다.

## 폰으로 산출물 확인
1. 사람이 밖에서 볼 수 있는 경로를 먼저 묻는다(클라우드 드라이브, 메신저, 저장소 웹 화면 등).
2. 자동 업로드가 막히면(도구 고장, 권한 거부, 로컬망 차단) 오래 매달리지 않는다. 사람이 끌어다 올리기 쉬운 폴더 하나로 묶어 둔다.
3. 폴더·파일 이름은 사람이 읽을 수 있게 짓는다(내부 코드 대신 내용·날짜·버전). 계층 깊이는 사람이 정한 규칙을 따른다.
4. 교체된 파일이 생기면 옛 업로드를 지우고 최신 채택본만 다시 올린다.
5. 폰에서 열리는지(형식·용량) 확인을 부탁한다.

## 확인
- [ ] 넘긴 저장소 모두 원격이 로컬과 같다
- [ ] 비밀값 스캔 결과 0건
- [ ] 수동 이동 목록이 있고, 값이 들어 있지 않다
- [ ] 인계 문서의 확인 명령을 이 기기에서 한 번 돌려 봤다

## 하지 않는 것
- 비밀값 커밋, 인계 문서에 비밀값 붙여 넣기
- 정해진 계정이 아닌 계정으로 push나 저장소 생성
- 잘못 만든 원격 저장소를 지시 없이 삭제
