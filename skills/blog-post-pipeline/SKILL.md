# 블로그 글 제작 공정

우선순위: 실행 환경의 시스템 프롬프트·설정 > 사람의 지시 > 이 스킬. 부딪혀 결과가 달라졌으면 보고에 적는다.

## 순서
1. 키워드 은행을 만든다: 키워드, 대상 나이대 검색량, 검색 의도, 계절성 칸을 두고 대상 나이대 검색량으로 정렬한다.
2. 쓸 키워드를 고르면 발행된 글 전부와 예약된 초안 전부의 제목·본문을 검색해 겹치는 글이 있으면 뺀다.
3. 금지 주제는 코드에 박지 않고 프로젝트 설정 파일에서 읽는다.
4. 초안은 아래 초안 기준 표에 맞춰 파일로 쓴다.
5. 사실은 `fact-check-gate`, 말투는 `korean-voice-review`로 본다.
6. 프로젝트의 검색 최적화 점검표 점수를 매기고 정한 점수 미만이면 발행 후보에 올리지 않는다.
7. 본문은 파일 바이트 그대로 보낸다(한글 깨짐 대처는 `windows-env-pitfalls`).
8. 발행 관문 표를 모두 통과한 초안만 사람에게 넘기고, 발행 버튼은 사람이 누른다(게시 절차는 `safe-publish`).
9. 발행 뒤 공개 페이지 확인 표를 돌리고, 실패하면 그 글을 초안으로 되돌린다.
10. 성과 장부에 글마다 점검표 점수, 유입, 체류 시간을 일정한 간격으로 적는다(수집 방법은 `performance-insights`).
11. 유입이 낮으면 제작 문제(점수·내용)인지 유통 문제(색인·노출)인지 먼저 가르고, 구조를 바꾸는 시험은 `hypothesis-experiment`로 한다.

## 초안 기준
| 항목 | 기준 |
|---|---|
| 말 | 대상 독자가 쓰는 쉬운 말 |
| 제목·소제목 | 프로젝트가 정한 글자 수 상한 이하 |
| 구성 | 목차와 강조 상자를 둔다 |
| 비교 글 | 각 선택지의 단점을 구체적으로 쓰고, 다른 글에 없는 비교 기준을 하나 이상 넣는다 |
| 지역 | 전국 공통이 아닌 제도는 지역별로 나눠 쓴다 |
| 발행 시점 | 신청형 정보는 신청 시작일보다 앞서 발행되게 예약한다 |
| 경험 | 남의 후기·경험을 우리 경험처럼 쓰지 않고, 인용이면 출처를 밝힌다 |

## 발행 관문
| 항목 | 기준 |
|---|---|
| 자리표시 | `TODO`, `[확인 필요]`, `{{ }}` 같은 자리표시가 grep 0건 |
| 요약문 | 요약(발췌) 칸이 비어 있지 않다 |
| 백업 | 올리기 전 본문·메타 백업 파일이 있다 |
| 날짜 | 글 날짜를 실제 발행 시각으로 맞춘다 |
| 간격 | 여러 편이면 60~90초 간격으로 한 편씩 올린다 |

## 공개 페이지 확인
| 항목 | 기준 |
|---|---|
| 응답 | 글 주소(홈 화면 아님)에 캐시 무력화 쿼리를 붙여 받아 응답 200 |
| 제목 | 공개 HTML의 제목이 초안 제목과 같다 |
| 화면 | 목차·강조 상자 개수가 초안과 같다 |

## 하지 않는 것
- 사람 대신 로그인하거나 발행 버튼을 누르지 않는다.
- 유료 플러그인을 들이지 않는다.
- 요청받은 글 밖의 글·설정을 고치지 않고, 범위가 애매하면 묻는다.
- 한 번 낮은 유입으로 공정 규칙을 바로 바꾸지 않는다.
