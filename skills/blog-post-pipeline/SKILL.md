# 정보 글 한 편

에이전트는 초안까지 쌓고, 발행은 사람이 한다. 공개된 페이지는 실제 HTML로 확인한다.

## 언제
- 지원금·정책·생활 정보 같은 정보 글을 새로 쓸 때
- 쌓아 둔 초안을 공개하기 전
- 정기적으로 초안을 여러 편 준비할 때

## 순서
1. 키워드 뱅크
   - 대상 독자가 검색하는 말을 뱅크 파일에 모은다. 도구 로그인은 사람이 한다.
   - 새 후보를 기존 글 전체와 예약 초안 전체에 대조해 중복을 뺀다.
   - 제외할 주제는 금지 목록에 박아 두지 않고, 나올 때마다 제외 사유와 함께 기록한다.
2. 사실 확정: 공고 원문으로 대상·금액·기한·신청처·공식 링크를 확정한다(fact-check-gate).
3. 차별점 한 줄: 같은 주제의 다른 글에 없는 것을 한 문장으로 쓴다. 비교 글이면 장점보다 단점을 구체적으로 쓴다. 차별점이 없으면 쓰지 않는다.
4. 초안
   - 독자 기준의 쉬운 말로 쓴다. 용어는 풀어 쓴다.
   - 소제목은 짧게, 목차를 두고, 강조는 핵심 몇 곳에만 한다.
   - 대상이 지역마다 다르면 글을 지역별로 나눈다.
   - 시기성 정보는 신청 시작일에 맞추지 말고 미리 낸다.
5. 문체 검수: 글 전체와 페이지 공통 문구(소개·안내·바닥글)를 korean-voice-review로 본다.
6. 재대조: 윤문 뒤 숫자·날짜·링크를 원문과 다시 맞춘다.
7. 여섯 항목 점검: 제목, 첫 문단, 대상, 금액, 기한, 공식 링크.
8. 검색 최적화 점검: 프로젝트에서 미리 정한 체크리스트와 통과 기준으로 본다.
9. 업로드 묶음 파일: 본문·제목·발췌·분류·대표 이미지를 한 파일로 만든다. 본문은 스크립트가 파일 바이트 그대로 보낸다. 모델이 한글 본문을 도구 인자에 다시 옮겨 적지 않는다.
10. 저장은 초안 상태로 한다. 공개·예약은 사람이 하거나 사람 승인 뒤에 한다.

## 공개 후 확인
| 항목 | 방법 |
|---|---|
| 응답 | 글 주소를 캐시 무효화 쿼리를 붙여 직접 요청, 정상 응답 |
| 내용 | 공개 HTML에서 제목·핵심 요소(강조 개수, 표, 계산기 등) 개수가 원고와 같다 |
| 잔재 | 자리 표시 문구 0, 발췌 있음, 날짜가 실제 발행 시각 |
| 위치 | 홈·목록 페이지는 본문을 렌더하지 않을 수 있으니 글 주소에서 본다 |

- 여러 편은 간격을 두고 한 편씩 공개하고, 편마다 확인한다.
- 확인에 실패한 글은 초안으로 되돌리고 보고한다.
- 실행자의 "통과" 보고가 아니라 공개 HTML을 근거로 쓴다.

## 성과 장부
- 글마다 점검 결과, 유입 경로, 체류 시간을 장부에 넣는다(performance-insights).
- 안 읽히면 생산 문제(글)인지 유통 문제(노출 경로)인지 먼저 가른다.
- 다음에 바꿀 것을 하나만 정한다.

## 확인
- 새 글 주제가 기존 글·예약 초안과 겹치지 않는다.
- 사실 확인 표의 모든 행이 확인됨이다.
- 공개 후 확인 표의 모든 항목을 공개 HTML로 확인했다.

## 하지 않는 것
- 직접 겪지 않은 경험을 겪은 것처럼 쓰지 않는다.
- 유료 플러그인·결제가 필요한 기능을 사람 확인 없이 도입하지 않는다.
- 쓰기 작업에 브라우저 조작을 쓰지 않는다. 제공되는 API나 도구가 있으면 그것을 쓴다.
- 요청 범위보다 넓게 기존 글을 다시 공개하거나 고치지 않는다.
