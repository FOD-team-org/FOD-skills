# 안전한 게시

우선순위: 실행 환경의 시스템 프롬프트·설정 > 사람의 지시 > 이 스킬. 부딪혀 결과가 달라졌으면 보고에 적는다.

## 순서
1. 후보를 고르기 전에 게시 기록 로그에서 그 항목의 상태 줄을 읽는다(`Select-String -Path <로그> -Pattern '<slug>'` / `grep -n '<slug>' <로그>`).
2. 산출물 메타 파일의 게시 필드(`published_at`, media id, 메모)를 파일 읽기 도구로 직접 읽는다(콘솔 한글 깨짐은 `windows-env-pitfalls`).
3. 둘 중 하나라도 애매하면 플랫폼의 최근 게시물 목록을 API로 받아 같은 캡션·링크가 있는지 대조한다.
4. 산출물 폴더나 부속 파일(썸네일·스토리 이미지)이 있다는 사실은 게시 여부의 근거로 쓰지 않는다.
5. 소재를 고르는 단계에서도 위임 전에 사건 날짜·지역·핵심 명사로 같은 로그를 grep해 이미 다룬 소재인지 본다.
6. 여러 회차가 같은 폴더에 쓸 수 있으면 회차 시작·빌드 직전·로그 기록 직전에 산출물 폴더·정본 파일·같은 날 다른 회차 후보가 있는지 본다.
7. 셋 중 하나라도 내 세션이 만들지 않은 것이면 새로 만들지 않고 이어받아 검수한 뒤 "어느 회차 제작·어느 회차 검수" 주석을 남긴다.
8. 정본 파일(덱 JSON 등)은 쓰기 전에 존재 여부부터 본다.
9. 게시 도구는 기본이 드라이런이고 `--confirm` 같은 명시 플래그가 있을 때만 실제로 올리게 만든다.
10. 드라이런 결과(무엇을·어디에·언제)를 목록으로 사람에게 보여 주고 목록 단위로 승인받는다.
11. 실제 게시는 비공개 또는 예약 상태로 먼저 올리고, 목록 API를 다시 읽어 들어간 것을 확인한 뒤 공개로 바꾼다.
12. 게시가 성공하면 그 자리에서 메타에 `published_at`과 media id를 쓰고 로그에 한 줄을 남긴다.
13. 공개 뒤에는 공개 페이지를 직접 받아 본문·링크·구조화 데이터가 원본과 같은지 본다.
14. 지표 수집과 판정은 `performance-insights`로 넘긴다.

## 점검
| 상황 | 규칙 |
|---|---|
| 예약 슬롯 | 슬롯마다 정확히 1개, 게이트를 통과한 것만, 다음 슬롯 분을 미리 채워 두지 않는다 |
| 하루 게시 수 | 채널별 상한과 최소 간격을 정하고 같은 분에 2개를 올리지 않는다 |
| 응답 실패·타임아웃 | 바로 재시도하지 않고 플랫폼 목록부터 조회해 이미 있으면 기록만 고친다 |
| 재시도 | 목록에 없을 때만 1회, 업로드 컨테이너를 만들기 전에 실패한 경우만 다시 만든다 |
| API 차단·호출 과다 | 1회 재시도 뒤 "수동 업로드 대기"로 기록하고 멈춘다 |
| 모르는 플래그 | 무시하고 기본 동작(전체 재게시)으로 넘어가지 않고 에러로 멈춘다 |
| 자격 파일 존재 | 키가 있다는 이유로 드라이런 가드가 풀리지 않게 한다 |
| 공개 주소가 404·옛 값 | CDN 캐시를 의심해 캐시버스터를 붙인 주소를 먼저 보고 그다음 원래 주소를 본다 |
| 예약 시각 | 현지 시각으로 정하고 API에 넣는 UTC 값을 따로 환산해 대조한다 |
| 상태 변경 API | 현재 상태 객체 전체를 읽어 복사한 뒤 바꿔 보낸다(빠진 필드가 기본값으로 덮이는 API가 있다) |
| 고정 댓글 | 달기 전에 댓글 목록을 조회해 이미 있으면 건너뛴다 |
| 예약분 점검 | 공개 시각 뒤 점검 작업이 공개 상태와 로그를 확인한다(작업 등록은 `routine-ops`) |
| 멱등 | 같은 입력으로 두 번 실행해도 게시는 1건이고 로그·메타·플랫폼 목록이 서로 같다 |
| 중복 사고 | 두 번 올라간 편은 실험 표본에서 빼고, 메타 링크를 남은 쪽으로 고치고, 삭제는 사람에게 요청한다 |

## 하지 않는 것
- 승인 없이 삭제·예약 취소·재업로드·공개 전환을 하지 않는다.
- 이미 공개한 게시물은 사람이 시키지 않으면 고치지 않는다.
- 댓글 답글은 실제로 달린 댓글에만 초안(2~3안과 해석)을 쓰고, 이미 답한 스레드는 빼고, 게시는 사람이 한다.
- 답글을 쓰기 전에 대상 글이 누구의 글인지(내 초안인지 남의 댓글인지) 확인하지 않고 넘어가지 않는다.
- 사람이 직접 발행하기로 한 채널(블로그 등)은 초안 저장까지만 한다.
- 게시 기능이 들어 있는 헬퍼 CLI를 다른 용도로 실행하지 않고 필요한 함수만 import한다.
- 게시 단계에 넘길 해시·ID를 기억으로 적지 않고 직전 명령 출력에서 복사한다.
- 짧은 시간에 몰아 올리지 않는다(과다 업로드와 중복·비공개 잔존본은 배포 축소로 이어진다).
