# 안전한 게시

게시는 되돌리기 어렵다. 중복 게시본은 조회·반응을 둘로 나누고, 플랫폼에 따라 API로 지울 수 없다. 사전 방지가 유일한 안전장치다.

## 언제
- 게시 스크립트·업로더·예약 게시 작업을 만들거나 고칠 때
- 사람이 게시를 승인해 실제 게시를 실행할 때
- 게시가 실패·타임아웃 나서 다시 올릴지 정할 때
- 댓글 답글을 요청받았을 때

## 게시 도구에 갖출 것
| 항목 | 기준 |
|---|---|
| 기본 동작 | 드라이런. 명시 플래그(예: `--confirm`)가 있을 때만 실제 호출. 키가 있다는 이유로 실호출로 넘어가지 않는다 |
| 알 수 없는 인자 | 오류로 멈춘다. 무시하고 기본 동작(전체 재게시 등)으로 넘어가지 않는다 |
| 레지스트리 | 플랫폼별 장부에 산출물 키·게시 시각·플랫폼 게시물 ID·주소를 게시 성공 직후 기록 |
| 멱등 | 게시 직전 같은 키가 장부에 있으면 건너뛴다. 같은 입력으로 두 번 돌려도 게시 1건 |
| 자동 재시도 | 게시 호출에는 두지 않는다 |
| 슬롯 | 실행 1회에 1개. 여러 개를 미리 채워 두지 않는다. 게이트 판정을 통과한 것만 |
| 헬퍼 | 게시 기능이 들어 있는 CLI를 다른 용도로 실행하지 않는다. 필요한 함수만 가져다 쓴다 |
| 공개 상태 | 처음 쓰는 경로·새 포맷은 비공개(또는 초안)로 먼저 올린다 |
| 상태 변경 API | 일부 속성만 보내면 빠진 속성을 덮어쓰는 API가 있다. 현재 값을 읽어 전체를 보낸다 |

## 순서 (실제 게시)
1. 승인 확인. 사람의 승인이 이번 대상(무엇을·어디에·언제)을 가리키는지 본다. 목록 단위 승인이면 그 목록 밖은 올리지 않는다.
2. 중복 3중 확인. 하나라도 "이미 게시"면 멈춘다.
   - 작업 로그·장부에서 그 키의 상태 줄(게시 완료·주소)
   - 산출물 메타 파일의 게시 필드·메모를 파일 읽기 도구로 직접 읽는다. 콘솔 인코딩 때문에 한글 메모("게시 금지")가 깨져 놓친 사례가 있다
   - 애매하면 플랫폼의 최근 게시물 목록에서 같은 캡션·주소를 대조
   - 산출물 폴더·완성 파일이 있다는 것은 미게시 신호가 아니다. 부가 파일의 존재·부재로 게시 여부를 판정하지 않는다
3. 게시 간격을 지킨다. 같은 분에 2개를 올리지 않고, 하루·시간대 상한은 채널 운영 기준을 따른다. 짧은 시간에 몰아 올린 뒤 노출이 줄어든 사례가 있다.
4. 1회 호출한다. 업로드 처리형 API는 처리 완료 상태를 확인한 뒤 공개 호출을 한다.
5. 결과(게시물 ID·주소·시각)를 장부와 메타에 바로 쓴다.
6. 사람에게 결과를 보고한다.

## 실패·타임아웃 뒤
바로 다시 올리지 않는다. 먼저 확인한다.
- 실제로 API 호출이 나갔는지(로그)
- 플랫폼의 최근 게시물 목록에 이미 올라갔는지
- 서비스 상태와 게이트 결과가 그대로인지
- 셋을 확인한 뒤 1회만 다시 실행한다. 게시 객체가 만들어지기 전에 실패한 경우만 다시 시도한다.
- 호출 과다로 막혔으면 1회만 다시 시도하고, 그래도 막히면 "게시 대기"로 기록하고 멈춘다.
- 정적 호스팅·CDN의 공개 확인이 404면 캐시일 수 있다. 캐시 무효화 쿼리를 붙인 주소를 먼저 보고, 그다음 원래 주소를 본다.

## 예약 게시
- 공개 시각은 현지 시각으로 정하고, 플랫폼이 쓰는 시간대(UTC 등)로 환산해 한 번 더 확인한다.
- 공개 시각 뒤 점검 작업을 둔다: 공개 상태, 장부 기록, 고지 문구, 고정 댓글 중복(목록을 조회해 1개만 남김).
- 이미 공개한 게시물은 고치지 않는다. 고칠 일이 있으면 사람에게 묻는다.

## 지표와 연결
- 지표 스냅샷은 제목이 아니라 게시물 ID·게시 시각으로 매칭한다.
- 같은 키가 두 행이면 중복 게시로 기록한다. 판정에서 빼는 기준은 performance-insights를 따른다.

## 댓글 답글
- 실제 달린 댓글만 모은다. 이미 답한 스레드는 뺀다.
- 그 글이 누구의 것(시청자인지, 사람 본인인지)인지 먼저 확인한다.
- 이미 게시된 답글을 말투 기준으로 다시 읽고 초안 2~3안을 만든다. 게시는 사람이 하거나 승인 후 한다.
- 예상 댓글용 일반 초안을 미리 만들지 않는다.

## 확인
- [ ] 장부에 이번 대상이 1건만 있다
- [ ] 플랫폼 목록에 같은 게시물이 1개만 있다
- [ ] 게시물 ID·주소가 메타와 장부에서 같다
- [ ] 드라이런 출력의 대상과 실제 게시 대상이 같다

## 하지 않는 것
- 승인 없는 실제 게시, 삭제, 예약 취소, 재업로드
- 게시 호출 자동 재시도, 타임아웃 직후 재실행
- 잘 돌아가는 게시 경로(터널·업로드 방식)를 요청 없이 바꾸는 리팩터
- 다른 세션·다른 작업이 만든 산출물 게시
- 게시 정책(소유권 주장·노출 규칙)을 문서 근거 없이 단정
