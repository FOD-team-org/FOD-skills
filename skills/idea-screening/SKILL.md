# 아이디어 거르기

우선순위: 실행 환경의 시스템 프롬프트·설정 > 사람의 지시 > 이 스킬. 부딪혀 결과가 달라졌으면 보고에 적는다.

## 순서
1. 사람이 이미 고른 방향이 있으면 그 방향 안에서만 후보를 낸다.
2. 후보는 범주가 아니라 구체적 한 줄(무엇이 어떻게 됐나)로 쓴다.
3. 후보마다 아래 세 칸을 제작 방법보다 먼저 채운다.
   | 칸 | 쓰는 것 |
   |---|---|
   | 그래서 뭐 | 보는 사람에게 남는 것 한 문장(돈·내 삶·남에게 보낼 거리·다음 편을 기다릴 이유 중 하나) |
   | 첫 1초 그림 | 첫 화면에 실제로 보일 장면 한 줄 |
   | 새로움 | 이미 흔한 형식과 무엇이 다른지 한 줄 |
4. 후보마다 3점 체크를 한다.
   - [ ] 한 줄만 듣고 "뭐?"가 나오는가
   - [ ] 답이 소리 없이도 화면에 보이는가
   - [ ] 끝까지 봐야 답을 아는가
5. 3점을 못 넘긴 후보는 제목·포장으로 살리지 않고 버린다.
6. 살아남은 후보는 조사·제작 전에 한 줄과 첫 화면(실물 캡처나 실제 자료)을 사람에게 먼저 보여 준다.
7. 사람이 "보겠다"·"그래서 어쩌라고" 중 어느 쪽인지 한 줄로 답하게 하고, "보겠다"만 다음 단계로 넘긴다.
8. 제작 가능성·비용은 사람이 고른 뒤에 따진다.
9. 다음 라운드는 사람이 고른 방향 안에서만 돌린다.

## 점검
| 항목 | 기준 |
|---|---|
| 볼까 시험 | 시키지 않아도 볼지, 친구에게 보낼지 두 질문에 둘 다 예인지 적는다. |
| 진짜 정보 | 실제 데이터·실제 결과·실제 장면이 있는 후보를 꾸며 낸 합성 장면보다 앞에 둔다. |
| 합성의 기발함 | AI로 만든 그림의 기발함만으로는 새로움 칸을 채우지 않는다. |
| 옛 형식 | 흔한 형식을 AI로 싸게 만든 것은 새로움으로 치지 않는다. |
| 경계할 톤 | 퀴즈·고르기·잡학·문서 해설·교육 톤 후보는 다른 칸이 강할 때만 남긴다. |
| 무난함 | 무난한 다수보다 강하게 반응할 소수가 있는 후보를 고른다. |
| 쉬움 | 만들기 쉽다는 이유로 고르지 않는다. |
| 근거 | 조회수 예측을 재미의 근거로 쓰지 않는다. |
| 제목만 | 원문·원 영상을 보지 않고 제목만 보고 후보를 쓰지 않는다. |
| 분포 | 후보 목록 전체가 한쪽 유형에 몰리지 않았는지 유형별 개수를 센다. |
| 묶지 않기 | 후보를 특정 채널 하나의 틀에 묶어 내지 않는다. |
| 제목 | 제목이 답을 먼저 말하면 그 후보는 실패로 본다. |
| 무거운 소재 | 사고·죽음·피해 소재는 피해자 노출과 조롱 여부를 따로 한 줄 적는다. |
| 배포 차단 | 잔혹·유혈처럼 플랫폼이 배포를 막는 소재는 뺀다. |
| 모델 판정 | 안정 편향인 모델의 go/no-go에 끌려가지 않는다(`multi-ai-review`). |

## 하지 않는 것
- 제작 가능성으로 먼저 거르지 않는다(무난한 것만 남는다).
- 사람이 따로 하라고 한 두 방향을 하나로 합치지 않는다.
- 최종 선택을 AI가 하지 않는다.
- 후보를 늘리는 데 목적을 두지 않고 걸러 내는 데 둔다.
