# 관찰 경로로 바꿔 넣기

## 언제
- 운영 중인 작업의 엔진·모델·프롬프트·규칙을 바꿀 때
- 결정적 판정 위에 LLM 판정을 더하려 할 때
- 새 작업이 원래 작업을 대신할 수 있는지 판단해야 할 때

## 관찰 경로 만들기
- 새 경로는 실제 행동(주문, 게시, 발송, 상태 변경)을 하지 않는다. 결과는 따로 떨어진 폴더에 쓴다.
- 운영 중인 "최신" 결과 파일을 덮어쓰지 않는다.
- 원래 경로의 결과는 비교에만 쓴다. 새 경로의 입력으로 넣지 않는다.
- 시험 실행에서 만든 초안에는 시험본 표시를 단다. 이 작업에만 적용한 설정 덮어쓰기를 목록으로 남긴다.
- 커밋되지 않은 변경이 있는 작업 트리에서 관찰 경로를 커밋하지 않는다.

## 비교
- 실행마다 원래 결과와 새 결과를 나란히 기록한다.
- 다른 판정은 세 가지로 나눈다: 원래가 맞음, 새 것이 맞음, 새 것이 잘못 막음.
- 관찰 경로 자체의 연속 실패 수를 본다. 비교 숫자만 보다가 관찰 경로가 수십 번 연속 실패한 것을 놓친 사례가 있다.
- 비교 기간과 통과 기준(일치율, 잘못 막음 상한)을 시작 전에 정한다.

## LLM 판정을 더할 때
- 승격 전까지 LLM 판정은 더하기만 한다. 상태를 바꾸거나 결정적 판정을 뒤집지 않는다.
- 결정적 결과와 A/B로 비교하고, 매매처럼 수치로 검증할 수 있는 일은 backtest-validation 기준을 통과한 뒤에만 승격한다.

## 바꿔 넣기
- 실패한 실행 결과는 올리지 않는다. 성공한 실행만, 원자적으로(임시 파일 → 이름 바꾸기) 바꿔 넣는다.
- 승격은 사람이 정한다. 비교 표와 남은 위험을 보고하고 기다린다.
- 원래 경로는 바로 지우지 않고 꺼 둔 상태로 남긴다. 되돌리는 명령을 운영 문서에 적는다.
- 사람이 관찰 없이 바로 바꾸라고 하면 비교 없이 바꿀 때의 위험을 한 줄로 알린다. 사람이 그대로 정하면 바꾸되, 원래 경로를 꺼 둔 채 남기고 한 번에 되돌리는 스위치를 둔다.

## 확인
- [ ] 관찰 경로가 실제 행동을 한 기록이 없다
- [ ] 운영 결과 파일이 관찰 경로 때문에 바뀌지 않았다
- [ ] 비교 표에 불일치 분류와 관찰 경로 실패 수가 있다
