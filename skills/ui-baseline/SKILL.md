# 화면 기준

우선순위: 실행 환경의 시스템 프롬프트·설정 > 사람의 지시 > 이 스킬. 부딪혀 결과가 달라졌으면 보고에 적는다.

목표는 잘 만든 SaaS 제품(개발자 도구·운영 콘솔)처럼 보이는 화면이다. 어두운 바탕, 얇은 선, 단정한 글자, 촘촘하지만 정돈된 목록으로 완성도를 만든다. 엑셀 같은 격자 표나 꾸밈 많은 랜딩 화면이 아니다.

우선순위: 사람의 지시 > REQUIREMENTS.md > 이미 있는 화면의 디자인 > 이 스킬. 사람이 브랜드 색·글꼴·밝은 테마를 주면 아래 디자인 값의 해당 칸만 바꾼다.

## 만드는 방법
- CSS 프레임워크·UI 라이브러리·아이콘 라이브러리·웹폰트·CDN을 쓰지 않는다.
- `frontend/src/tokens.css`(디자인 값)와 `frontend/src/styles.css`(클래스) 두 파일로 만들고 진입 파일에서 한 번 불러온다.
- 색·글자 크기·간격·둥글기·그림자는 tokens.css의 CSS 변수로만 정의하고, 나머지는 var(--…)로만 쓴다. 인라인 style은 쓰지 않는다.
- 아이콘은 기능이 있는 곳(사이드바 메뉴, 펼침 화살표, 상태 표시)에만 16px 인라인 SVG(stroke 1.5, currentColor)로 직접 그린다.
- 같은 역할에는 같은 클래스를 쓴다. 화면마다 새 모양을 만들지 않는다.
- 기존 화면을 다시 짤 때는 기존 문구·id·입력과 버튼의 동작·API 호출을 유지한다. 구조와 클래스는 바꿔도 된다.

## 앱 구조
| 영역 | 규칙 |
|---|---|
| 사이드바 | 왼쪽 고정. 맨 위 서비스 이름(14/600)과 기준 정보 한 줄(12 보조, 자료·요구에 있는 사실만). 그 아래 화면 메뉴(아이콘+이름, 현재 화면은 hover 면+본문색). 폭 768px 이하에서는 위쪽 가로 바로 바뀐다 |
| 페이지 머리 | 아래 선 하나. 왼쪽 제목, 오른쪽 주 동작 버튼. 제목은 이 화면의 일이고 사이드바의 서비스 이름을 되풀이하지 않는다 |
| 설명 줄 | 제목 아래 보조색 한 문장으로 이 화면에서 무엇을 정하는지 쓴다. 입력 이름을 나열하지 않는다 |
| 도구 줄 | 조건 입력을 32px 높이로 한 줄에 놓는다. 라벨은 입력 위 12/500 보조색. 좁으면 줄바꿈 |
| 요약 줄 | 라벨(12 보조)·값(20/600) 쌍 2~4개를 한 줄에 놓고 얇은 세로선으로 나눈다. 숫자마다 카드를 만들지 않는다. 적용 조건·계산 시각은 그 아래 캡션 |
| 패널 | 패널 면+선+8px. 머리 줄(구역 제목, 건수, 오른쪽 보조 동작) 아래 목록이나 표 |

## 목록과 상세
- 사람이 판단하는 묶음(주문·노선·설비·티켓 등)은 격자 표가 아니라 목록 행으로 보인다. 행 하나: 상태 점·아이콘, ID와 사람이 아는 이름, 핵심 값 2~4개를 고정 폭 열로 정렬, 오른쪽 펼침 화살표.
- 행을 누르거나 Enter를 누르면 행 아래에 상세가 펼쳐진다(button + aria-expanded + aria-controls, 또는 details/summary). 상세 안의 여러 줄 자료는 표로, 순서가 있는 단계는 세로 선과 점으로 잇는 단계 목록으로 보인다.
- 표: 머리 행 12/500 보조색·옅은 아래 선, 행은 아래 선만(세로선·줄무늬·바깥 테두리 없음), hover 면. 숫자 오른쪽, 글자 왼쪽 정렬. 넓으면 표 영역 안에서 가로 스크롤.
- 상태 배지: 6px 점+글자(12/500), 필요하면 상태 면을 깐다. 테두리 없음. 버튼처럼 보이지 않게 한다.
- 버튼: 주 버튼은 한 화면에 하나. 보조 버튼은 투명 면+진한 선+본문색, hover 면. 위험 동작은 위험 글자색.
- 알림: 상태 면+상태 점+이유+다음 행동(다시 시도 버튼 등). 패널 위쪽 전체 폭.

## 상태
- 처음 열면 바로 쓸 수 있게 한다. 결과 화면이면 기본 조건(날짜 포함)으로 계산한 결과를, 입력 화면이면 다음 행동을 보인다. 빈 화면이나 "조건을 고르고 누르세요"로 시작하지 않는다.
- 요청 중: 결과 자리에 글자로 알리고, 제출 버튼은 요청 중에만 끄고 "계산 중…"처럼 글자를 바꾼다.
- 0건: 패널 안 가운데에 이유 한 줄과 다음 행동 버튼.
- 실패: 이전 결과를 지우고 알림에 이유와 다음 행동.
- 제외·경고: 요약 줄 아래에 이유별 건수를 보이고, 누르면 해당 목록이 펼쳐진다. 처리되지 않은 것을 숨기지 않는다.
- 조건을 바꿔 다시 계산하면 요약 줄 전체가 새 값으로 바뀐다.

## 내용과 문구
- 결과를 판단하는 데 필요한 것만 둔다. 사람이 아는 이름을 ID와 함께 보인다.
- 라벨은 명사, 버튼은 동사("다시 계산", "저장"). 단위는 열 머리나 값 옆에 한 번 쓴다. 환영·광고 문구는 쓰지 않는다.
- 숫자는 Intl.NumberFormat(ko-KR)로 형식화한다. 날짜는 YYYY-MM-DD, 시각은 HH:mm(초가 필요하면 HH:mm:ss)로 입력·자료와 같은 형식으로 쓰고 white-space: nowrap.
- 자료와 요구에 없는 조직·사람·장소 이름이나 설명을 지어내지 않는다.

## 접근성
- 데이터 표는 table·caption·thead·th scope="col"로 짓는다.
- 모든 입력에 label을 연결한다. 오류는 필드 옆에 쓰고 aria-describedby로 연결하며 aria-invalid를 단다. 제출하면 첫 오류로 포커스를 옮긴다.
- 필터를 바꾸면 "N건 중 M건"을 aria-live="polite"로 알린다.
- 누르는 요소는 button이다. :focus-visible에 2px 강조색 테두리와 2px 간격을 준다. tabindex는 0보다 크게 쓰지 않고, 확대·축소를 막지 않는다.
- 상태는 색과 함께 글자로 구분한다. 본문·보조 글자 대비는 4.5:1 이상이다. 날짜 입력 등 기본 컨트롤이 어두운 바탕에서 보이게 :root에 color-scheme: dark를 준다.
- 폭 400px에서 쓸 수 있다. 사이드바는 위쪽 바로, 도구 줄·요약 줄은 줄바꿈, 목록 행은 핵심 값만 남기고 줄바꿈. 넓은 표만 자기 영역 안에서 가로 스크롤한다.

## 넣지 않는 것
- 흔한 AI 화면 문법: 히어로·환영 문구·소개 문단, 이모지, 반짝이·장식 아이콘·일러스트, 그라데이션, 반투명 유리 효과, 빛 번짐, 모든 블록에 같은 둥근 카드와 그림자, 큰 숫자 카드 줄, 보라·남색 계열 강조, "~를 혁신하세요" 같은 문구.
- 요구에 없는 차트·테마 전환·애니메이션·설정 화면.

## 끝내기 전 점검 (브라우저 없이)
각 명령의 결과가 0줄이어야 한다.
- 색 값은 tokens.css에만: `grep -rnE "#[0-9a-fA-F]{3,8}\b|rgba?\(" frontend/src --include=*.css --include=*.tsx | grep -v tokens.css`
- 글자 크기는 변수로만: `grep -nE "font-size:\s*[0-9]" frontend/src/styles.css`
- 인라인 스타일 없음: `grep -rn "style={{" frontend/src`
- 금지 효과 없음: `grep -rnE "gradient|backdrop-filter" frontend/src`
- 의존성(package.json)에 react·react-dom 말고 화면 라이브러리가 없다.
