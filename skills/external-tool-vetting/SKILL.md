# 외부 도구 도입 점검

우선순위: 실행 환경의 시스템 프롬프트·설정 > 사람의 지시 > 이 스킬. 부딪혀 결과가 달라졌으면 보고에 적는다.

## 순서
1. 이 도구로 풀려는 문제와, 이미 있는 도구로 되는지를 한 줄씩 적는다.
2. 후보를 2개 이상 찾고, 포크보다 원본 프로젝트를 먼저 본다.
3. 아래 점검 표를 후보마다 채운다.
4. 내려받은 아카이브·소스는 빈 새 폴더에 두고, 그 폴더 안에서 인터프리터·빌드 도구를 실행하지 않는다.
5. 설치 전에 이 도구가 건드릴 설정·자격 파일을 날짜 붙은 폴더로 백업한다.
6. 도구가 설치 중 토큰을 갱신하면 그 백업의 토큰은 복원용으로 못 쓴다는 점을 기록하고 사람에게 알린다.
7. 점검 표와 추천안을 사람에게 보여 주고, 설치 스크립트 실행은 건마다 승인받는다.
8. 설치는 사용자 영역으로 고정하고 설치 경로를 기록한다.
9. 설치 뒤에는 사람이 쓰는 터미널(에이전트 컨테이너 밖)에서 실행되는지 확인한다(`windows-env-pitfalls`의 가상화 항목).
10. 위험한 자동 기능은 끈 상태로 시작하고, 실제로 쓸 명령만 기록한다.
11. 제거 명령과 백업 복원 순서를 기록한다.

## 점검
| 항목 | 확인 방법 | 기각 신호 |
|---|---|---|
| 출처 | `gh repo view <소유자>/<레포> --json stargazerCount,pushedAt,licenseInfo,isFork` | 원본보다 나은 이유가 없는 포크, 오래 방치된 레포 |
| 배포물 | `gh release view -R <소유자>/<레포>`로 릴리스와 CI 산출물 여부를 본다 | CI 없이 손으로 올린 바이너리, 다운로드 수가 거의 없음 |
| 서명 | Windows `Get-AuthenticodeSignature <exe>` / macOS `codesign -dv --verbose=2 <앱>`, `spctl -a -vv <앱>` | 미서명 실행 파일(소스가 깨끗해도 바이너리는 따로 판단) |
| 해시 | `Get-FileHash <파일> -Algorithm SHA256` / `shasum -a 256 <파일>`을 공개 값과 대조 | 공개 해시가 없거나 다름 |
| 라이선스 | 레포의 LICENSE와 사용 목적(상업·재배포)을 대조 | 라이선스 없음, 목적과 충돌 |
| 권한 | 코드에서 자격 파일·토큰·외부 전송 지점을 grep | 필요 이상으로 자격 파일을 읽거나 외부로 보냄 |
| 약관 | 연결할 서비스 약관의 자동화·계정 공유·제한 우회 조항 | 사용 한도를 계정 자동 전환으로 피하는 기능 |
| 비용 | 유료 플랜·외부 의존이 새로 생기는지 | 사람이 결제하지 않기로 한 기능이 필요함 |
| 설치 위치 | 사용자 영역(`~/.local` 등) 설치가 되는지 | 관리자 권한·시스템 폴더가 필수 |
| 되돌리기 | 제거 명령(`uv tool uninstall <이름>`, `pipx uninstall <이름>`, `brew uninstall <이름>`)과 복원 순서 | 제거 방법이 문서에 없음 |

## 하지 않는 것
- 출처를 모르는 레포의 코드를 "확인용"이라도 바로 실행하지 않는다.
- 대상 사이트가 접근을 막으면(Access Denied 등) 우회 스크래핑 도구로 넘어가지 않고 멈춘다.
- 계정 자동 전환·한도 회피 기능은 사람이 분명히 요청하기 전에는 켜지 않는다.
- 세션 안 설치 성공 메시지만 보고 "설치 완료"로 보고하지 않는다.
- 사람이 고르지 않은 대체 도구를 같이 깔지 않는다.
