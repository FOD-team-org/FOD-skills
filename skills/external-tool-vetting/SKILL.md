# 외부 도구 도입 점검

## 언제
- 공개 저장소 등에서 받은 도구·실행 파일을 설치하기 전
- 에이전트용 플러그인·스킬·MCP 서버를 추가하기 전
- 계정·인증 정보를 다루는 도구(계정 전환, 토큰 관리)를 쓰기 전
- 외부 저장소 코드를 실행하라는 요청을 받았을 때

## 점검표
| 항목 | 확인 | 기각 신호 |
|---|---|---|
| 출처 | 원 저장소와 관리자, 포크면 상위 프로젝트 | 원본을 알 수 없는 재배포본 |
| 활동 | 최근 커밋, 이슈 응답, 사용자 수(별·다운로드) | 다운로드 극소, 관리 중단 |
| 빌드 | 소스에서 빌드되는가, CI와 릴리스 서명 | 미서명 실행 파일만 배포, CI 없음 |
| 라이선스 | 파일 존재와 종류, 재배포·수정 조건 | 표기 없음(스킬·글을 옮겨 쓸 때) |
| 권한 | 읽고 쓰는 경로, 네트워크 호출, 인증 정보 접근 | 필요 이상으로 홈 전체·키 파일 접근 |
| 약관 | 연결하는 서비스의 이용 약관과 충돌(계정 공유, 자동 전환으로 한도 우회, 스크래핑) | 보호 조치 우회로 읽힐 기능 |
| 자동 기능 | 자동 전환·자동 갱신·자동 실행 | 기본으로 켜져 있고 끌 수 없음 |
| 대체재 | 같은 일을 하는 다른 도구 1~2개 비교 | |
- 소스를 읽을 수 있으면 인증 정보를 어디에 저장하고 어디로 보내는지 직접 본다.

## 설치
1. 점검표 결과와 추천·대안을 사람에게 보고하고 승인받는다.
2. 설치가 건드릴 설정·인증 파일을 백업한다. 설치 중 토큰이 갱신되면 그 백업의 토큰은 복원에 못 쓴다는 점을 사람에게 알린다.
3. 사용자 영역(홈 아래 도구 폴더)에 설치한다. 시스템 전역·관리자 설치는 피한다. 런타임 버전은 그 도구 전용으로 고정한다.
4. 패키지 앱 안의 세션이면 AppData 가상화를 피한다(windows-env-pitfalls).
5. 사람의 터미널(세션 밖)에서 실행해 보이는지 확인한다.
6. 위험한 자동 기능은 끄고, 수동 명령만 쓴다고 운영 문서에 적는다.

## 외부 코드 실행
- 받은 저장소는 새 빈 폴더에 두고, 그 폴더 안에서 인터프리터를 실행하지 않는다. 내가 쓴 스크립트는 다른 폴더에 두고 경로를 인자로 넘긴다.
- 접근 차단(Access Denied·403)을 우회하는 스크래핑 코드는 실행하지 않는다. 막히면 멈추고 보고한다.

## 되돌리는 법 (설치 전에 적어 둔다)
- 제거 명령, 지울 폴더, 되돌릴 설정 파일과 백업 위치
- 바뀐 환경 변수·PATH 항목

## 확인
- [ ] 점검표 각 행에 확인 결과가 있다
- [ ] 사람의 승인 기록이 있다
- [ ] 세션 밖 실행을 확인했다
- [ ] 되돌리는 법이 운영 문서에 있다

## 하지 않는 것
- 미서명·출처 불명 실행 파일 설치
- 약관 위험 기능(자동 계정 전환 등)을 요청 없이 켜기
- 외부 스킬·글의 원문을 그대로 옮기기(아이디어만 우리 말로 쓰고 출처를 적는다)
