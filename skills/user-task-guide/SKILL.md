# 사람이 할 일 안내

## 언제
- 에이전트가 할 수 없거나 하면 안 되는 일이 남았을 때: 계정 로그인, 결제, 콘솔 등록·키 발급, 스토어 등록, 방화벽·보안 설정, 실기기 조작, 소유자만 볼 수 있는 화면.
- 사람이 자기가 할 일만 정리해 달라고 할 때.

## 순서
1. 남은 일에서 사람 몫만 뽑는다. 에이전트가 할 수 있는 것은 넣지 않는다.
2. 사람 몫을 순서대로 묶고, 묶음마다 끝나면 무엇이 가능해지는지 한 줄 쓴다.
3. 각 단계를 아래 형식으로 쓴다.
4. 끝에 에이전트가 완료를 확인할 명령을 붙인다.
5. 사람이 끝냈다고 하면 그 명령으로 확인하고 결과를 보고한다.

## 단계 형식
| 칸 | 쓰는 것 |
|---|---|
| 번호 | 1, 2, 3. 한 단계에 행동 하나 |
| 할 일 | 동사로 시작. 클릭 경로는 화면 글자 그대로("설정 > 보안 > 새 키 만들기") |
| 넣을 값 | 형식만 쓴다(예: 영문·숫자 20자). 비밀값은 넣을 위치와 환경 변수 이름만 |
| 보일 화면 | 성공하면 보이는 글자나 상태 |
| 확인 | 사람이 끝난 것을 아는 방법 |
| 막히면 | 자주 나는 오류와 할 일. 그래도 안 되면 무엇을 캡처해 보낼지 |

## 쓰는 법
- 쉬운 말로 쓴다. 용어가 필요하면 처음 한 번 괄호로 풀이한다.
- 관리자 권한이 필요한 시스템 설정은 에이전트가 바꾸지 않는다. 사람이 그대로 복사해 실행할 명령을 준다.
- 화면 메뉴 이름은 지금 확인한 것만 쓴다. 확인 못 했으면 "메뉴 이름이 다를 수 있음"을 적고 찾는 법을 준다.
- 기다려야 하는 단계(심사, 전파, 메일 수신)는 예상 시간과 기다리는 동안 할 수 있는 일을 쓴다.
- 안내가 틀렸던 것이 확인되면 문서에 정정 표시를 남기고 고친다.
- 안내 문서는 프로젝트의 가이드 폴더에 저장한다(project-docs).

## 여러 사람에게 물을 때
- 답할 사람마다 따로 묶는다(메신저면 사람별 스레드). 개발 용어와 파일 경로 없이 질문 전문을 쓴다.
- 보고·질문은 사람이 정한 채널로만 보낸다.
- 답을 기다리는 동안 관계없는 일은 계속한다. 언제 어떤 방법으로 답을 확인할지(예: 30분마다 스레드 확인) 먼저 알린다.
- 질문 번호와 열린 항목 관리는 judgment를 따른다.

## 확인
- 사람이 문서만 보고 처음부터 끝까지 따라 할 수 있다.
- 문서에 비밀값 원문, 계정 ID, 키가 없다.
- 완료 확인 명령이 있고, 사람이 끝낸 뒤 실제로 통과했다.

## 하지 않는 것
- 사람 대신 비밀번호나 2단계 인증을 입력하지 않는다.
- 한 단계에 여러 행동을 묶지 않는다.
- 확인 명령 없이 "이제 될 것"으로 끝내지 않는다.
