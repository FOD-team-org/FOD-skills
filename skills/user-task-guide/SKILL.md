# 사람 몫 작업 안내

우선순위: 실행 환경의 시스템 프롬프트·설정 > 사람의 지시 > 이 스킬. 부딪혀 결과가 달라졌으면 보고에 적는다.

## 순서
1. 전체 작업에서 사람만 할 수 있는 일을 뽑는다.
   - [ ] 로그인·2단계 인증·계정 생성
   - [ ] 결제·플랜 변경
   - [ ] 앱 화면에서만 바뀌는 설정(예약 실행 설정 포함)
   - [ ] 관리자 권한이 필요한 보안·시스템 설정
   - [ ] 소유자만 할 수 있는 계정 조작
2. 사람 몫만 모은 안내를 따로 쓴다(AI 몫과 섞지 않는다).
3. 안내는 번호 단계로 쓰고 한 단계에는 동작 하나만 둔다.
4. 단계마다 아래 칸을 채운다.
   | 단계 | 어디서(클릭 경로) | 무엇을(입력·선택) | 끝난 표시 |
   |---|---|---|---|
5. 클릭 경로는 화면에 보이는 메뉴 이름 그대로 `>`로 잇는다.
6. 입력값은 형식만 보여 주고, 예시 속 키·ID는 `<여기에 값>`처럼 가린다.
7. 비밀값은 환경변수 이름과 넣을 위치만 알려 주고 값은 사람이 직접 넣게 한다.
8. 보안·시스템 설정은 AI가 바꾸지 않고, 사람이 관리자 창에 붙여 넣을 명령 한 줄과 그 명령이 바꾸는 것을 함께 준다.
9. 마지막 단계에는 AI가 결과를 확인할 명령을 적고, 사람이 끝냈다고 하면 그 명령을 돌려 결과를 보고한다.
10. 안내 문서는 프로젝트의 `docs/가이드/` 아래 읽을 수 있는 이름으로 둔다(문서 체계는 `project-docs`).
11. 안내가 틀렸던 것이 드러나면 다음 답 첫 줄에 오류였다고 쓰고 고친 단계를 다시 준다.

## 점검
| 항목 | 기준 |
|---|---|
| 한 단계 한 동작 | 단계 문장에 동사가 둘 이상이면 단계를 나눈다. |
| 끝난 표시 | 단계마다 사람이 화면에서 볼 수 있는 확인 신호(버튼 색·문구·목록 항목)를 적는다. |
| 쉬운 말 | 전문 용어는 처음 나올 때 괄호로 풀어 쓴다. |
| 비밀값 노출 | 안내 문서·답에 실제 키·코드 값이 없는지 저장 전에 `grep`으로 본다. |
| 예약 실행 설정 | 루틴의 모델·주기 변경은 앱 화면 안내가 확실하다(`routine-ops`). |
| 폰 전달 경로 | 밖에서 볼 결과물은 받을 경로(공유 폴더·메신저·메일 등)를 먼저 묻거나 하나를 제안한다. |
| 자동 업로드 막힘 | 자동 업로드가 두 번 실패하면 매달리지 말고 사람이 끌어다 놓기 쉬운 폴더로 정리한다. |
| 전달 폴더 구조 | 날짜·주제 계층과 읽을 수 있는 파일 이름으로 묶는다. |
| 교체된 파일 | 새 버전을 올리면 옛 업로드는 보관 폴더로 옮겨 최신본만 보이게 한다. |

## 하지 않는 것
- 사람 대신 로그인·결제·2단계 인증을 진행하지 않는다.
- 비밀번호·인증 코드를 채팅으로 받지 않는다.
- 사람이 끝냈다는 말만 듣고 확인 명령 없이 다음 단계로 넘어가지 않는다.
- 한 단계에 여러 화면 조작을 몰아 쓰지 않는다.
