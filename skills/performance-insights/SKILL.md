# 게시 후 지표

우선순위: 실행 환경의 시스템 프롬프트·설정 > 사람의 지시 > 이 스킬. 부딪혀 결과가 달라졌으면 보고에 적는다.

## 순서
1. 게시물마다 장부 한 줄을 만든다: 게시 시각·게시물 ID·형식·실험 팔·제목.
2. 게시 후 +3시간·+24시간·+72시간에 지표를 모은다.
3. 모은 값은 장부 CSV에 시점별로 덧붙이고, 덮어쓰지 않는다.
4. 수치마다 출처를 적는다(API 응답인지, 사람이 관리 화면에서 읽은 값인지).
5. 영상은 리텐션 곡선과 이탈이 몰린 지점(초)을, 글은 체류 시간과 유입 경로를 함께 모은다.
6. 비교는 같은 형식·같은 게시 시간대·같은 경과 시간끼리만 한다.
7. 기준선(최근 N편 중앙값)과 잡음 범위(같은 기준선의 흔들림 폭)를 먼저 구하고, 그 범위 밖일 때만 차이로 본다.
8. 낮은 성과는 생산 문제(내용·첫 화면)인지 유통 문제(노출·유입)인지 먼저 가른다.
9. 원인 가설을 쓰고 규칙 개정안은 "제안"으로만 적는다.
10. 판정은 `hypothesis-experiment`의 판정 규칙으로 메인·사람이 하고, 다음 편에서 조정은 하나만 시험한다.
11. 숫자는 표로 보고하고 보고 시각을 붙인다.

## 점검
| 항목 | 기준 |
|---|---|
| API 지연 | 게시 직후 0이 나오면 지연으로 보고 몇 시간 뒤 다시 조회하며, 0을 결과로 적지 않는다. |
| 성급한 메모 | 지연 값으로 쓴 결론 메모는 재조회 뒤 정정 표시와 함께 고친다. |
| 판정 시점 | 게시 후 48시간이 지난 표본만 판정에 넣는다. |
| 제외 | 이상치·표본 수 미달·중복 게시 건은 판정에서 빼고 뺀 이유를 적는다. |
| 매칭 | 스냅샷과 장부는 제목이 아니라 게시 시각·게시물 ID로 맞춘다. |
| 중복 ID | 같은 게시물 ID가 장부에 두 번 있으면 판정에서 빼고 `safe-publish`의 중복 확인을 본다. |
| 지표 키 | 지표 이름은 코드에 하드코딩하지 않고 등록부에서 읽어 파생한다(없는 키는 건너뛰고 기록). |
| 집계 범위 | 점수 집계는 최근 N개 창을 정해 두고 창 크기를 보고에 적는다. |
| 호출 과다 | 지표 API가 호출 과다로 막히면 1회만 재시도하고 나머지는 다음 수집 시점으로 미룬다. |
| 자동 변경 금지 | 지표 수집 루틴은 장부만 쓰고 플레이북·정본은 고치지 않는다. |
| 공개 | 공개 문서·레포에 실제 지표 수치를 넣지 않는다. |

## 하지 않는 것
- 한 편의 수치로 규칙을 바꾸지 않는다.
- 다른 시간대·다른 경과 시간의 수치를 섞어 비교하지 않는다.
- 사람이 읽은 수치와 API 수치를 출처 표시 없이 한 칸에 섞지 않는다.
- 판정과 정본 갱신을 수집 루틴에 맡기지 않는다.
