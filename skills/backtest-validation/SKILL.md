# 백테스트 검증

## 언제
- 새 전략·필터·지표를 시험할 때
- "이 전략 쓸 만하냐", "수익률 얼마냐"는 질문에 답할 때
- 관찰·모의 운용으로 넘기기 전에

## 먼저 고정할 것
결과를 보기 전에 실험 기록에 적는다.
- 통과 기준: 연 수익률, 최대 낙폭(MDD), 손익비(PF)의 하한·상한
- 탐색 횟수: 시험할 파라미터 조합 수. 결과를 보고 늘리지 않는다
- 비교 기준선: 단순 보유, 무작위 진입 같은 기준 전략
- 판정 등급: 배포 가능, 좁은 조건에서만, 기각. "승인된 전략 없음"도 정상 결과다

## 순서
1. 학습 구간(IS)에서 파라미터를 고른다.
2. 검증 구간에서 고른다.
3. 표본 밖(OOS)에서 한 번 본다. OOS를 본 뒤 다시 조정하지 않는다.
4. 워크포워드로 구간을 밀며 반복한다.
5. 몬테카를로(거래 순서 섞기)로 낙폭 분포를 본다.
6. 수수료·슬리피지를 올려 가며 민감도를 본다.
7. 종목별로 나눠 일부 종목에만 기대는지 본다.

## 가정
| 항목 | 기준 |
|---|---|
| 비용 | 매수·매도 양쪽 수수료와 세금, 슬리피지 |
| 체결 | 손절·익절을 종가로 판정하는지 장중 터치로 판정하는지 명시 |
| 보유 | 최대 보유 기간, 동시 보유 수 상한, 종목당 비중 상한 |
| 유니버스 | 그 시점에 존재하던 종목만(point-in-time). 상장폐지 종목 포함 여부 점검 |
| 누출 | 미래 정보 누출 검사기를 두고, 일부러 누출시킨 음성 시험으로 검사기가 잡는지 확인. 구간 사이 퍼지·엠바고 |

## 보고
- CAGR, MDD, PF, 거래 수, 승률을 항상 같이 쓴다. 하나만 쓰지 않는다.
- 같은 표에 기준선 수치를 둔다.
- 거래 수가 적으면 수치를 믿지 않는다고 적는다.
- 너무 좋은 결과(연 수십 % 이상, 낙폭 거의 없음)는 누출·비용 누락·생존 편향부터 의심한다.
- 핵심 수치는 다른 백테스트 엔진이나 독립 구현으로 한 번 맞춰 본다.
- 실패한 전략도 최고·최악 구간 메타데이터와 함께 기록에 남긴다. 같은 시도를 되풀이하지 않게 한다.

## 다음 단계
- 신호를 더할 때는 기존 신호와 상관이 낮은 것을 고른다.
- 통과한 전략도 바로 실주문으로 가지 않는다. 모의 운용 → 관찰(shadow-lane-cutover) → 실주문(trading-automation-safety) 순서를 지킨다.
- LLM은 매매 판단 경로 밖에 둔다. 보고서 작성·요약에만 쓴다.

## 하지 않는 것
- 결과를 본 뒤 기준 바꾸기, OOS 뒤 재조정
- 비용 없는 수익률 보고, 지표 하나만 보고
