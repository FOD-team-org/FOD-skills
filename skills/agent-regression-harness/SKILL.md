# 에이전트 회귀 측정

제품 안 LLM 기능의 방어는 llm-feature-guard, 테스트가 결함을 잡는지는 mutation-check를 따른다. 이 스킬은 에이전트 자체의 행동을 잰다.

## 언제
- 에이전트의 지침·모델·스킬을 바꾼 뒤
- 훅·권한 가드를 만들거나 고친 뒤
- 정기 점검(예: 주 1회)

## 시나리오
- 실제로 맡기는 일 단위로 10~20개를 고정한다. 예: 브리핑에서 링크 보존, JSON만 출력, 외부 발송 전 확인 요청, 비밀값 가림, 보고 형식.
- 채점은 규칙으로 한다: JSON 파싱, 언어 비율, 금지어, 줄 수, 정규식. LLM 채점에 기대지 않는다.

## 실행기와 기준선
- 모의 실행기와 실제 실행기를 둘 다 둔다. 모의 실행으로 하네스 자체를 먼저 검증한다.
- 직전 결과를 기준선으로 저장하고 비교한다.
- 지연 시간은 흔들리므로 큰 폭(예: 두 배)일 때만 회귀로 센다.
- 종료 코드를 나눈다: 평가에서 진 것은 요약을 남기고 0, 회귀 실패 옵션을 켰을 때만 별도 코드, 설정 오류(도구 없음, 키 없음, 기준선 파싱 실패)는 또 다른 0 아닌 코드. 평가 결과와 고장을 섞지 않는다.

## 격리
- 하네스는 운영 에이전트의 설정·코드를 바꾸지 않는다. 격리된 홈·설정으로 돈다.
- 예약 등록은 하네스 저장소 밖에서 한다. 저장소에는 스크립트만 둔다.

## 가드 자가 시험
- 지침 파일에 무작위 표식 값을 넣고, 새 세션에 그 값을 답하게 해 파일이 실제로 읽히는지 본다.
- 같은 시험 세션에서 막혀야 할 동작(범위 밖 쓰기, 금지 명령)을 한 번씩 시도하게 해 모두 막히는지 본다. 막히면 우회하지 않고 정해진 한 줄만 답하게 한다.
- 시험 세션은 세션 기록을 많이 남긴다. 별도 폴더나 표식으로 나눠 실제 작업 기록과 섞이지 않게 한다.

## 확인
- [ ] 모의 실행이 통과한 뒤 실제 실행을 했다
- [ ] 기준선 대비 회귀 항목과 지연 변화를 보고했다
- [ ] 가드 시험에서 막혀야 할 동작이 모두 막혔다
